## 1. 范围与职责

2D 引擎是**固定功能**单元,把图元变成帧缓冲里的像素。它只做三件事,但必须做对:

| 功能 | 命令 | 说明 |
|---|---|---|
| **填充** | `2D_FILL`(0x10) | 用纯色填一个矩形(清屏、背景、调试色块) |
| **位块传送** | `2D_BLIT`(0x11) | 矩形拷贝,支持颜色键(精灵透明)、水平/垂直翻转、源格式转换 |
| **三角形光栅化** | `2D_DRAW`(0x12) | 读**顶点输出缓冲**,按边方程光栅化,按重心坐标插值颜色,混合后写帧缓冲 |

另有三条控制命令:`2D_SET_REG`(0x13,写引擎寄存器)、`2D_FLUSH`(0x14,冲刷写缓冲),
`0x15–0x17` 保留(见 §4.6)。

**分工(与 shader 核的边界)**

```
shader 核(ISA.md)                        2D 引擎(本文档)
  顶点变换 + 颜色计算  ──写──► 顶点输出缓冲 ──读──► 光栅化 → 插值 → 混合 → 帧缓冲
  逐像素的通用计算(雾化、光照…)          固定功能的像素流水(填充/拷贝/光栅/混合)
```

- **顶点由 shader 算,像素由 2D 引擎算**:ISA §7.2 的 `gouraud` 内核把变换后的 `{x, y, r, g, b, a}` 写进
  顶点输出缓冲;2D 引擎负责把它变成像素。
- **两个引擎之间没有缓存一致性协议**,可见性完全靠"命令完成 + `FENCE`"(CMDS.md §10.3):
  `2D_DRAW` 必须用 `wait_id` 指向那个 LAUNCH 的 `signal_id`,否则会读到未写完的顶点。
- **不需要 shader 参与的路径**:清屏、纯色块、精灵合成直接走 `2D_FILL`/`2D_BLIT`,不启 LAUNCH。

**明确排除(v1 不做,避免范围失控)**

| 不做 | 理由 |
|---|---|
| 深度缓冲 / 深度测试 | 本项目的目标是 2D 图元与 2D 变换后的三角形,不做 3D 场景 |
| 透视除法与透视校正插值 | 顶点坐标由 shader 输出为**屏幕空间**,不带 w;仿射插值即正确语义(§5.4) |
| MSAA / 抗锯齿 | 像素中心采样 + top-left 规则足够,且便于逐像素对拍 |
| 纹理解压、mipmap、各向异性过滤 | 只保留最近邻点采样(§3 的 `TEX_*`,列入 v2) |
| 计算类(卷积/形态学) | 那属于 shader 核的领域 |

## 2. 数据格式

本节是**顶点与帧缓冲格式**。ISA §7.2 的示例内核、CMDS §7 的 `FB_BASE`、
以及后续驱动/参考模型都以本节为准。

### 2.1 顶点格式

| `vtx_format` | 每顶点 | 布局 | 用途 |
|---|---|---|---|
| 0(默认) | **6×f32 = 24B** | `{x, y, r, g, b, a}`(按序,小端) | v1:`gouraud` 内核的输出(ISA §7.2) |
| 1(v2 预留) | 8×f32 = 32B | `{x, y, r, g, b, a, u, v}` | 贴图三角形 |
| 2–255 | — | — | 保留(非 0/1 即 `BAD_FORMAT`) |

- 参考模型只实现 `vtx_format = 0`;`1`(带 uv)属 v2,收到即报 `BAD_FORMAT`
- `x, y`:**屏幕空间像素坐标**,FP32;**左上角为原点、y 向下**(与帧缓冲行序一致,不引入翻转)
- `r, g, b, a`:FP32,**范围 [0, 1]**(越界按 §6.3 的 clamp 处理,不报错)
- **为什么否掉定点顶点格式**:计划文档里曾建议顶点坐标用 s16.15 定点。否掉的理由有两条:
  ① shader 只产出 FP32(ISA §3.3),要让顶点变定点就得在内核里加转换指令(每字段 1~2 条,
  一个 24B 顶点 3~6 条),而 ISA §8.1 的实测显示 `gouraud` 每次访存已要跨 3.73 个 32B 行,再加重排字段不划算;
  ② 定点化会丢精度,而且把"格式转换"塞进了通用核。**转换属于固定功能单元**:2D 引擎写像素时按
  `FB_FORMAT` 做一次(§6.3),只做一次,且不占 shader 的发射槽。
- 顶点在缓冲里**紧凑排列(AoS)**:第 i 个顶点自 `vtx_addr + i × 顶点字节数` 起。ISA §7.2 已指出这会让
  "同字段跨 lane"的访存退化(每次跨 6 行)—— 这是**已知代价**,换来"一个顶点一次写完"的简单性;
  要恢复合并需要 SoA,属于 ISA §10 的访存优化路线,与本文档无关。

### 2.2 帧缓冲格式

| `FB_FORMAT` | bpp | 位型 | 说明 |
|---|---|---|---|
| 0(默认) | 32 | **ARGB8888** | `[31:24]=A, [23:16]=R, [15:8]=G, [7:0]=B` |
| 1 | 16 | RGB565 | `[15:11]=R, [10:5]=G, [4:0]=B`,无 alpha(当 1.0) |
| 2–255 | — | — | 保留(`BAD_FORMAT`) |

> **为什么是 ARGB 而不是 RGBA**:帧缓冲的取色约定必须与**已经存在的东西**一致 —— ISA 的
> `clear` 内核写 `0xFF00FF00`(不透明绿)、`anim`/`car` 的颜色常量、以及驱动侧 SDL/PPM/ASCII 的
> 取色路径 `(c>>16)&0xFF, (c>>8)&0xFF, c&0xFF` **都**把 alpha 放在最高字节。让引擎用 `[31:24]=R`
> 会让它**算出来**的像素(混合、格式转换)在显示时 R/B 互换, 而"原样搬移"的像素看起来正常 ——
> 这种"只错一半"的 bug 从画面上极难看出来(`make car --view` 实测踩过: 高光那块颜色不对)。

- 帧缓冲基址由 CMDS §7 的 `FB_BASE` 给出(R/W,复位值 `0x1000_0000`)
- 行跨距 `FB_STRIDE`(字节,0 = 紧凑 = `FB_WIDTH × bpp/8`);
  像素 `(x, y)` 的字节地址 = `FB_BASE + y×FB_STRIDE + x×bpp/8`
- 帧缓冲的**尺寸与格式**(`FB_WIDTH`/`FB_HEIGHT`/`FB_STRIDE`/`FB_FORMAT`)是 §3 的引擎寄存器,
  由驱动经 `2D_SET_REG` 写入。**为什么不做成 CP MMIO**:它们只被 2D 引擎消费,host 侧回读没有实际用途
  (驱动写什么自己知道);shader 核需要画布信息时从常量区参数取(ISA §3.4),不去碰 MMIO
  (内核访问 MMIO 是架构错误,CMDS §8.2 第 6 项)。若将来确需 host 回读,再在 CP MMIO 里开镜像。

### 2.3 颜色位型(命令参数里的颜色)

`2D_FILL`/`2D_BLIT` 的 `color`/`colkey` 按**目标格式**解释:ARGB8888 用整个 32b;
RGB565 只用低 16b(高位忽略)。这样驱动不必做格式转换就能复用同一个颜色常量。

## 3. 引擎寄存器(经 `2D_SET_REG` 写)

**唯一写入路径是 `2D_SET_REG`(0x13)**(CMDS.md §12);它与 `WRITE_REG`(0x01,写 CP 的 MMIO 窗口)的区别,
在于进的是 2D 引擎自己的寄存器空间。未列出的偏移 = 保留 ⇒ `BAD_REG`;所有保留位必须为 0。

| 偏移 | 名称 | 宽度 | 复位值 | 说明 |
|---|---|---|---|---|
| 0x00 | `FB_WIDTH` | 16b | 0 | 帧缓冲宽(像素),1..4096 |
| 0x04 | `FB_HEIGHT` | 16b | 0 | 帧缓冲高(像素),1..4096 |
| 0x08 | `FB_STRIDE` | 16b | 0 | 行跨距(字节),0 = 紧凑;非 0 时须 ≥ 一行字节数且 4B 对齐 |
| 0x0C | `FB_FORMAT` | 8b | 0 | §2.2 的格式编码 |
| 0x10 | `SCISSOR_X` | 16b | 0 | 裁剪框左上角 x |
| 0x14 | `SCISSOR_Y` | 16b | 0 | 裁剪框左上角 y |
| 0x18 | `SCISSOR_W` | 16b | 0 | 裁剪框宽,0 = 不裁剪 |
| 0x1C | `SCISSOR_H` | 16b | 0 | 裁剪框高,0 = 不裁剪 |
| 0x20 | `BLEND_MODE` | 2b | 0 | §6.2 的混合模式 |
| 0x24 | `COLKEY` | 32b | 0 | 颜色键(按目标格式解释,§2.3) |
| 0x28 | `COLKEY_EN` | 1b | 0 | 1 = 等于颜色键的源像素丢弃(精灵透明) |
| 0x2C | `TEX_BASE` | 32b | 0 | **v2**:纹理基址 |
| 0x30 | `TEX_FORMAT` | 8b | 0 | **v2**:与 `FB_FORMAT` 同编码 |
| 0x34 | `TEX_FILTER` | 1b | 0 | **v2**:0 = 最近邻(唯一实现) |
| 0x38–0x3F | — | — | — | 保留 |

- 引擎寄存器**只能写、不能读**(写入路径唯一)。需要"读回"的场合由驱动自己记住写过的值。
  > 状态与错误为可观测性起见放在 CP 的 MMIO 窗口(与 GEMM 的 `0x60`/`0x64` 同一约定,CMDS §7):
  > `0x68 2D_STATUS`(bit0 BUSY、bit1 DONE、bit2 ERROR)、`0x6C 2D_ERROR`(枚举见 §7.3)。
  > **注意**:2D 引擎本体尚未实现(SPEC §5),这两个寄存器当前读回 0 —— 已登记为 SPEC §7 第 1 条的待实现项。
- `FB_WIDTH/HEIGHT/STRIDE/FORMAT` 必须在**任何** 2D 命令之前写好(`FB_WIDTH == 0` ⇒ `BAD_FORMAT`)。
  这取代了此前"帧缓冲尺寸/格式由 `FB_BASE` 与 GFX.md 共同描述"的悬空说法(SPEC §7-2 由此关闭)。

## 4. 命令编码(opcode 0x10–0x17,权威)

每条命令都遵循 CMDS §2.2 的两字头:`word0 = {length_words[31:16], cmd_flags[15:8], opcode[7:0]}`、
`word1 = {signal_id[31:16], wait_id[15:0]}`;参数自 `word2` 起。**保留位必须为 0**,否则 CP 侧判 `CMD_ERROR`(CMDS §2.4)。

### 4.1 `2D_FILL`(0x10,`length_words = 6`)

```
word2: dst_addr[31:0]      ; 目标像素地址(全局); 按目标格式的像素字节数对齐(ARGB8888 ⇒ 4B)
word3: color[31:0]         ; 目标格式的颜色位型(§2.3)
word4: x[15:0] | y[31:16]  ; 矩形左上角(像素)
word5: w[15:0] | h[31:16]  ; 尺寸, 1..4096
```

- 语义:把 `[x, x+w) × [y, y+h)` 与裁剪框的交集填成 `color`。**`dst_addr` 是像素 `(x, y)` 的地址锚点**,
  同行其余像素由 `FB_STRIDE` 推出(`dst_addr + dy×stride + dx×bpp/8`),且必须落在帧缓冲窗口内
- 校验:`w`/`h` ≥ 1;`x+w ≤ FB_WIDTH` 且 `y+h ≤ FB_HEIGHT`,除非 `SCISSOR_W/H` 非 0 且请求被裁剪框完全包含
  (否则 `OUT_OF_RANGE`)
- 完成:全部像素写完,且写缓冲已冲刷到足以被后续 `FENCE` 观察到(§6.4)

### 4.2 `2D_BLIT`(0x11,`length_words = 9`)

```
word2: src_addr[31:0]
word3: dst_addr[31:0]
word4: src_stride[15:0] | reserved[31:16]   ; 字节, 0 = 紧凑(按 flags.SRC_FMT 的像素字节数 × w)
word5: x[15:0] | y[31:16]                   ; 目标位置(像素)
word6: w[15:0] | h[31:16]
word7: flags[31:0]  ; bit0 COLKEY_EN, bit1 FLIP_X, bit2 FLIP_Y, bit3 SRC_FMT(0=ARGB8888, 1=RGB565)
word8: colkey[31:0] ; word7.bit0=1 时有效
```

- 语义:逐像素拷贝;`FLIP_X/Y` 在**目标**坐标系镜像;`SRC_FMT` 与 `FB_FORMAT` 不同时按 §6.3 转换一次
- 颜色键:源像素值 == `colkey` ⇒ **丢弃该像素**(目标保持原值),用于精灵透明。比较按**源格式**的位宽
  (`SRC_FMT=ARGB8888` 用 32b、`RGB565` 用低 16b);§2.3 的"按目标格式解释"只针对 `2D_FILL` 的颜色参数
- `src_stride` 非 0 时必须 ≥ 一行的字节数(`w × 源像素字节数`),否则行会重叠 ⇒ `BAD_PARAM`
- 校验:`w`/`h` ≥ 1,`src_addr`/`dst_addr` 按各自像素字节数对齐,`src_stride` 4B 对齐
- **本命令不做透明混合**:需要半透明用 `COLKEY_EN=0` + `BLEND_MODE=SRC_OVER`(§6.2)

### 4.3 `2D_DRAW`(0x12,`length_words = 8`)

```
word2: vtx_addr[31:0]      ; 顶点输出缓冲基址(全局, 4B 对齐)
word3: vtx_count[31:0]     ; 顶点数, 必须是 prim 的整数倍
word4: vtx_format[7:0] | prim[15:8] | reserved[31:16]
word5: flags[31:0]         ; bit0 CLIP_EN(1 = 按 §3 的裁剪框裁剪), 其余保留
word6: reserved            ; 必须为 0
word7: reserved            ; 必须为 0
```

- `vtx_format` 见 §2.1;`prim`:0 = 三角形列表(每 3 个顶点一个三角形),1–255 保留(`BAD_PRIM`)
- 语义:按 §5 的光栅化规则画 `vtx_count/3` 个三角形;顶点坐标已在屏幕空间(**不做变换、不做透视除法**)
- 校验:`vtx_count ≥ 3` 且是 3 的倍数;`vtx_addr` 4B 对齐;`vtx_addr + vtx_count × 顶点字节数` 不越出全局内存
- **上游依赖**:顶点由 shader 内核写(ISA §7.2),因此 `word1.wait_id` 必须指向那个 LAUNCH 的 `signal_id`
  (CMDS §10.3:跨引擎可见性靠"完成 + FENCE")

### 4.4 `2D_SET_REG`(0x13,`length_words = 4`)

```
word2: reg_off[15:0] | reserved[31:16]   ; §3 的寄存器偏移
word3: value[31:0]
```

- 校验:`reg_off` 必须是 §3 列出的偏移(4B 对齐),否则 `BAD_REG`;`value` 的保留位必须为 0
- 写入只影响**后续命令**:引擎不重放已入队命令(CP 顺序分发,CMDS §9)

### 4.5 `2D_FLUSH`(0x14,`length_words = 2`)

无参数。语义:把 ROP 写缓冲里未落盘的像素全部写出,并**保证对后续 `FENCE` 可见**。
用途:一帧结束时、或在 host/其它引擎要读帧缓冲之前调用(CMDS §10.3)。

### 4.6 保留(0x15–0x17)

| opcode | 预留用途 |
|---|---|
| 0x15 | `2D_DRAW_INDEXED`(索引顶点) |
| 0x16 | `2D_BLIT_STRETCH`(缩放位块传送) |
| 0x17 | `2D_SET_PALETTE`(调色板 / CLUT) |

在实现之前,这三条按 CMDS §2.4 处理(`length_words ≥ 2`、保留位为 0),参数语义未定
⇒ **本版本不应被驱动使用**。

## 5. 光栅化规则

像素级验证靠"逐像素 diff",所以本节必须精确到**舍入与边界**。

### 5.1 采样与坐标

- 像素 `(px, py)` 的**采样点**是它的中心:`(px + 0.5, py + 0.5)`
- `x` 向右、`y` 向下,原点在帧缓冲左上角(与 §2.1 的顶点坐标一致)
- 顶点顺序**顺/逆时针都接受**:内部按面积符号统一(§5.3),不做背面剔除

### 5.2 边方程(定点)

屏幕坐标先转定点:`X = round(x × 65536)`、`Y = round(y × 65536)`(**s32.16**,16 位小数)。
对三角形 `v0, v1, v2` 定义三条边的函数:

```
e0(p) = (X1 - X0)*(p.Y - Y0) - (Y1 - Y0)*(p.X - X0)     ; 边 v0→v1
e1(p) = (X2 - X1)*(p.Y - Y1) - (Y2 - Y1)*(p.X - X1)     ; 边 v1→v2
e2(p) = (X0 - X2)*(p.Y - Y2) - (Y0 - Y2)*(p.X - X2)     ; 边 v2→v0
```

- setup 阶段一次算好系数(每条边是 `A*x + B*y + C` 的形式);逐像素 3 次乘加,
  或用增量法(`p.X += 1` 时 `e += A`)—— 教学实现**先用乘加版**以便与参考模型逐位一致,
  增量版作为性能优化并单独验证
- 面积 `area = e0(v2)`(把 `v2` 代入 `e0`)= 2 × 有向面积;`area == 0` ⇒ 退化三角形,**整块丢弃**(不报错)
- 定点精度取 16 位小数的理由:顶点来自 FP32 屏幕空间值、像素中心是 `.5`,16 位小数足以让
  "恰好落在边上"的判定稳定;坐标 ≤ 4096 ⇒ `X ≤ 2^28`,s32.16 的乘加在 64 位中间结果里不溢出

### 5.3 填充规则(top-left rule)

令 `area > 0` 为正面(否则把三条边的符号一起取反,使 `area > 0`)。像素被覆盖的判据:

```
inside ⟺ (e0 > 0 或 (e0 == 0 且 边0 是 top/left 边))
      且 (e1 > 0 或 (e1 == 0 且 边1 是 top/left 边))
      且 (e2 > 0 或 (e2 == 0 且 边2 是 top/left 边))
```

"top/left 边"的判据(与 D3D/GL 一致):边 `(dx, dy)` 满足 `dy > 0`,或 `dy == 0 且 dx < 0`。

- **为什么必须有这条规则**:两个共享边的三角形若都把边上的像素算进去,就会重复写同一个像素
  ⇒ 半透明叠加时接缝变深。top-left 规则保证每个像素只被覆盖它的某一个三角形写一次
- 重心坐标 `λ0 = e1(p)/area`、`λ1 = e2(p)/area`、`λ2 = e0(p)/area`,三者之和恒为 1
  (定点下可能有 ±1 LSB 误差 ⇒ 参考模型必须用**同一套定点算术**复算,不能用 Python 浮点)

### 5.4 属性插值

- 颜色按重心坐标**线性插值**:`c(p) = λ0×c0 + λ1×c1 + λ2×c2`(逐通道 R/G/B/A)
- **不做透视校正**(§1 已排除 w):坐标已是屏幕空间,仿射插值就是正确语义
- 覆盖判定用定点(§5.2)、颜色插值建议用 **FP32**(与 ISA 的 FP32 顶点一致)⇒ 两条路径互不影响

### 5.5 裁剪

- `CLIP_EN=1` 时,像素还须落在 §3 的裁剪框
  `[SCISSOR_X, SCISSOR_X+SCISSOR_W) × [SCISSOR_Y, SCISSOR_Y+SCISSOR_H)` 内
- 裁剪是**逐像素**的(不做几何裁剪):简单、易与参考模型对齐;顶点落在屏幕外也照常 setup,
  只要边方程的中间结果不溢出(坐标 ±32768 像素以内安全)
- `SCISSOR_W == 0` ⇒ 不裁剪

## 6. 混合与写像素

### 6.1 像素流水

```
光栅化(覆盖+颜色) → 颜色键丢弃(COLKEY_EN) → 混合(BLEND_MODE) → 目标格式转换 → ROP 写缓冲 → 帧缓冲
```

### 6.2 混合模式

| `BLEND_MODE` | 公式(逐通道 R/G/B/A) | 说明 |
|---|---|---|
| 0 `NONE` | `dst = src` | 覆盖(默认) |
| 1 `SRC_OVER` | `dst = src×a + dst×(1-a)` | 标准 alpha 叠加;alpha 通道本身也用同式 |
| 2 `ADD` | `dst = min(src + dst, 1.0)` | 加法混合(高光/闪光) |
| 3 | 保留 | `BAD_REG` |

- 用 FP32 运算,最后按 §6.3 转换;**只在写像素时舍入一次**(避免"先量化再混合"的色带)
- `a` 取源像素的 alpha(不读目标 alpha)

### 6.3 目标格式转换

| 目标 | 规则 |
|---|---|
| ARGB8888 | `v8 = clamp(round(v × 255), 0, 255)`,四通道,打包成 `A<<24 \| R<<16 \| G<<8 \| B`;`round` = 四舍五入到最近整数(半值向上) |
| RGB565 | R/B 各 5 位、G 6 位:`r5 = clamp(round(r × 31), 0, 31)`、`g6 = clamp(round(g × 63), 0, 63)`、`b5` 同 `r5`;**不做抖动** |

- `clamp` 在舍入前作用于 [0,1]:`v < 0 ⇒ 0`、`v > 1 ⇒ 1`(源颜色越界不报错)
- 参考模型必须用同一规则(否则逐像素 diff 会在 ±1 上红一片)

### 6.4 写缓冲(ROP buffer)

- 每 2D 引擎一个写缓冲(容量 **8 条 32B 行**,按字地址合并):同一行的多次写合并为一次突发
- 冲刷时机:① `2D_FLUSH`;② 缓冲满;③ 命令完成(命令完成的定义就包含"已冲刷到对后续 `FENCE` 可见")
- 与 shader 侧共用同一套带宽;跨引擎可见性只有 `FENCE` 一条路径(CMDS §6.5/§10.3)

## 7. 完成、依赖与错误

### 7.1 完成判据

与 LAUNCH/GEMM 一致(CMDS §4.3/§6.11):命令的所有像素已写入帧缓冲(写缓冲已冲刷)⇒ 完成。
完成且 `signal_id != 0xFFFF` ⇒ `SEM[signal_id] += 1`,并置 `IRQ_STATUS[IRQ_2D_DONE]`(CMDS §7.4)。

### 7.2 状态寄存器

`2D_STATUS`(CP MMIO `0x68`):bit0 BUSY(命令执行中)、bit1 DONE(上一条命令已完成)、bit2 ERROR(`2D_ERROR != 0`)。
`2D_ERROR`(CP MMIO `0x6C`):写任意值清零(与 `CP_ERROR`/`SM*_ERROR` 同一约定,CMDS §7)。

### 7.3 错误枚举(`2D_ERROR`)

| 值 | 名称 | 触发条件 |
|---|---|---|
| 0 | `NONE` | 无错误 |
| 1 | `BAD_FORMAT` | `FB_FORMAT`/`SRC_FMT` 为保留值;`FB_WIDTH/HEIGHT` 为 0 |
| 2 | `BAD_REG` | `2D_SET_REG` 的偏移非法或保留、写入值的保留位非 0,或**取值越界**(`FB_WIDTH=0`、`BLEND_MODE=3` 等,§3) |
| 3 | `BAD_ALIGN` | `dst_addr`/`src_addr`/`vtx_addr` 未按像素/顶点字节数对齐 |
| 4 | `OUT_OF_RANGE` | 矩形或几何超出帧缓冲(且未被裁剪框完全包含) |
| 5 | `BAD_PRIM` | `vtx_count` 不是 3 的倍数,或 `prim` 未实现 |
| 6 | `BAD_PARAM` | 尺寸为 0、`length_words` 与命令不符、保留字段非 0、**保留 opcode(0x15–0x17)** |
| 7–15 | 保留 | |

引擎出错时:停止处理该命令,**不写信号量**,由 CP 置 `CP_ERROR = ENGINE_FAULT`(CMDS §8.1)并置 IRQ;
权威细节在 `2D_ERROR`(与"`SM*_ERROR` 权威"同一原则)。

## 8. 性能模型(设计目标值)

前提与 ISA §8.1 同:时钟 200MHz、每 SM 每周期 1 条 warp 指令。**下列数字是设计目标,不是实测值**。

| 操作 | 目标 | 说明 |
|---|---|---|
| `2D_FILL` | **1 像素/周期** | 纯写路径;640×480 = 307200 像素 ⇒ 307k 周期 ≈ **1.5 ms** |
| `2D_BLIT` | 1 像素/周期(读写各一次访存) | 帧缓冲带宽是最可能的瓶颈 |
| `2D_DRAW` | setup 常数开销 + ~1.6 周期/覆盖像素 | 边方程 3 乘加(或增量 3 加)+ 插值 + 混合 |
| 写缓冲 | 每行一次突发 | 与 shader 的 `st.g` 共用同一套带宽 |

**"为什么需要这个引擎"的量化**(用**实测数字换算到硬件周期**,而不是仿真墙钟):

| 做法 | 每像素成本 | 640×480 一帧 |
|---|---|---|
| shader 逐像素填充(`clear.S`,实测 307200 像素 = 307283 周期,4 warp/1 SM) | ~1.0 周期/像素/SM | ~1.5 ms(两 SM 同时填 ~0.8 ms) |
| shader 逐像素画有插值+混合的三角形(同 `anim.S` 量级:约 30 条 lane 指令/像素) | ~1.9 周期/像素(8 warp) | ~2.9 ms 起,且每像素都要取指译码 |
| `2D_FILL` 固定功能 | 1 像素/周期(单引擎) | ~1.5 ms,**且不占 shader 发射槽** |
| `2D_DRAW` 固定功能 | ~1.6 周期/覆盖像素 | setup 与插值都是硬连线,**无取指/译码/谓词开销** |

结论(比"引擎更快"更准确的说法):

1. **填充**上固定功能只比 shader 快约 2×(shader 已经很擅长规则的逐像素写);
2. 真正的差距在**光栅化+插值+混合**:通用核要 30+ 条 lane 指令/像素,固定功能是硬连线;
3. 结构性收益是**释放 shader 核**:填充/合成走 2D 引擎时,SM 可以去算顶点或做通用计算。

| 模块(golden model) | **Python 参考实现逐像素 diff** | `tests/gfx2d_ref.py`(§5/§6 的独立重写)+ `run_tests.py` 第 ⑪ 节,5 个场景 4096 像素逐位一致 |
| 系统 | 驱动 → CP → 2D → 读回帧缓冲 | `shader→2D` 用例(`gouraud` → `2D_DRAW`)与**参考应用 `sw/demo/car.cpp`**: 每帧 `FILL`+`BLIT`+`DRAW`(`wait_id` 等 LAUNCH) |

### 9.1 分层验证计划

| 层 | 手段 | 用例 |
|---|---|---|
| 单元 | 定点边方程与填充规则的定向测试 | 边界像素(`e == 0`)、退化三角形、共享边不重复写 |
| 模块(golden model) | **Python 参考实现逐像素 diff** | `2D_FILL` 矩形、`2D_BLIT`(含颜色键/翻转)、`2D_DRAW`(纯色/渐变三角形) |
| 系统 | 驱动 → CP → 2D → 读回帧缓冲 | 每帧"清屏 + 一个三角形";与 shader 顶点输出联调(`wait_id` 依赖) |
| 边界 | 格式与舍入 | RGB565 转换、`a=0`/`a=1`、颜色越界 clamp、颜色键命中 |

### 9.2 参考模型的落点建议

- **Python 参考模型**:`sim/simulator/tests/gfx2d_ref.py` —— 吃**同一份 cp-script**,按 §5/§6 算出期望帧缓冲,
  再与模拟器 `--dump` 出来的帧缓冲逐位比较(见 `sim/simulator/README.md` §4.1 的用法)。
- **C++ 实现**:`sim/simulator/2D-engine/gfx2d.cpp`,由 CP 的 `exec_2d` 调用,复用 `Memory` 的
  `ld_global`/`st_global`;`2D_STATUS`/`2D_ERROR` 经 `cp.read_reg` 暴露(CMDS §7 的 `0x68`/`0x6C`)。
  写路径经 ROP 写缓冲按 32B 行合并,`2D_FLUSH` 与命令收尾都会冲刷(§6.4)。
- **对拍口径**:颜色比较必须用 §6.3 的同一舍入规则、覆盖判定必须用 §5.2 的同一套定点
  ⇒ 不允许"参考模型用浮点、RTL 用定点"这种必然对不上的组合。

### 9.3 参考应用: `sw/demo/car.cpp`(两种画法, 同一幅画)

`make car`(默认)与 `make car-shader` 渲染同一场景, 用来量化 §1 的分工:

| | 2D 引擎路径(默认) | 逐像素 shader 路径(`--shader`) |
|---|---|---|
| shader 的工作 | `sw/kernels/car_vtx.S` 只算 **6 个顶点**(1 warp) | `sw/kernels/car.S` 每线程算一批像素 |
| 像素的工作 | 11×`2D_FILL` + `2D_BLIT`(颜色键) + `2D_DRAW`(混合) | SIMT 核逐像素 |
| 实测(128×64) | **53 周期/帧** | **33834 周期/帧** |

两条路的背景与精灵像素**逐位相同**(同一个 `Scene` 参数 + 同一个参考模型), 差别只在 2D 路径多一层
半透明高光。这不是"引擎更快"的泛泛之谈: 53 周期只是"启动内核算 6 个顶点"的成本, 像素工作完全不占
SM 的发射槽 —— 与 §8 的结论(差距在光栅化与释放 shader 核, 而不是单纯的填充速度)一致。
