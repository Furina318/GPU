## 1. ISA 设计决策记录(ADR D1–D20)

下表是 ISA 每项设计取舍的完整理由。手册 §5/§6 只给规则,这里给"为什么",以及与备选方案的比较。

| # | 决策 | 理由 / 代价 |
|---|---|---|
| D1 | warp = 8 lane | 教学规模;32 lane 调试代价陡增。8 lane 也正好让"4 warp × 8 lane = 32 线程/SM"与编程模型里的 `<<<num_warps, 8>>>` 对齐。升级路径:提高 vlen |
| D2 | `pred` 统一在 [28:26],I/S 型 imm 压缩为 9b | 编码统一 > imm 宽度:谓词化是 SIMT 每条指令都要用的东西,位置恒定让译码只有一条路径。代价:(a) I/S 立即数只有 ±255;(b) 非 4KB 对齐常量的构造变贵 ⇒ 常量一律走常量内存;(c) U 型因此必须放弃谓词字段。**已否决的备选**:2b pred + imm10(丢掉 `@!p`,而 `@!p` 正是"条件写入"写法的基础);按格式分别放 pred(省一位却把译码分派复杂化) |
| D3 | 仅 32 位字访存 | 合并器简化一个数量级;字节打包用逻辑指令。代价:RGBA8888 的按通道写要读-改-写(所以 clear 直接写整字);字节/半字访存排在扩展路线 |
| D4 | `fma` 无谓词字段 | R4 型没有空位;active mask 自动屏蔽已保证正确性(前提:FP 非 trapping、无副作用)。代价:**比 active_mask 更细的条件累加不能用 fma**,必须退回带谓词的 `fmul`+`fadd` 或重排成分支 |
| D5 | `exit` 必须均匀 | 非均匀退出的语义复杂,初版不做;尾部处理走谓词。代价:内核无法让"已完成的 lane 提前退出"来省时间 |
| D6 | 全部 warp 常驻,无多波次 | 使 barrier = kernel 级同步,概念清晰。代价:每 kernel ≤ 8 warp(用 barrier 时 ≤ 4) |
| D7 | 单实例 barrier + 同 SM 约束 | 命名 barrier / 跨 SM barrier 留待扩展。红利:硬件只需一个到达计数器 |
| D8 | 参数走常量内存 | 无 ABI 设计负担;合并器广播读,零额外硬件。代价:每次读参数都要过访存路径 ⇒ 内核应一次性 `ld.g` 到寄存器复用 |
| D9 | `setp` 目标仅 p1..p3 | p0 硬连线恒真;`@!p` 覆盖取反需求 |
| D10 | `br.simt` 显式收敛点操作数 | 收敛点由编译器/汇编器给出,硬件不做分支预测、不做收敛推断。代价:每条条件分支前多 1 条 `ipdom` |
| D11 | 无 atomics / ballot | 初版内核不需要;列于扩展路线。**连带后果值得记住**:没有 vote ⇒ 循环次数必须由标量算出 ⇒ `divu` 从"可选"变成"必需" |
| D12 | 新增整数 `imad`(R4 型 funct3=001) | "基址 + 索引×步长"在目标内核里出现 3 次(gouraud 2 次、matmul 1 次),用 mul+add 要 2 条指令且多占临时寄存器;硬件复用已有乘加器 ⇒ 面积增量≈0。已否决备选:让汇编器做 mul+add 合并(需要证明目标寄存器死亡,不如一条真指令干净、可读) |
| D13 | `setp` 改用 R 型的字段位置:`cond[31:29]` + `family=funct3` + `pdest=rd` | v0.1 的 setp 图有 bit 28/27(family 与 pred)与 bit 24..20(op 与 rs2)两处重复占用,**无法译码**。修完顺带把条件扩到 6 个(le/gt/feq/fne 全部到位),代价为 0 —— 用到的都是原本空着的位 |
| D14 | 非法情形一律做成**可检测的架构错误**,不写"未定义行为" | 栈溢出、未对齐、发散中 barrier、漏 `ipdom` 都能用 1~2 个比较器检出。理由:调试预算最贵,而"未定义行为"在仿真里表现为安静的错数据。代价:每 SM 一个错误码寄存器 + 停机逻辑 |
| D15 | SIMT 栈帧含 `fall_pc` 与 `mask_pending` | 缺 `fall_pc` 则嵌套发散无法恢复 else 入口;缺 `mask_pending` 则因 taken 路径会改写谓词而无法反推未执行 lane。代价:帧从 3 字段变 5 字段(≈3×32b),8 深栈也只有 ~96B/warp |
| D16 | `lui`/`ipdom` 放弃谓词字段,换 20 位立即数 | 保留 pred 则立即数只剩 17 位,`sext(imm17)<<12` 连 0x1000_0000 都够不到;而"条件地装常量"没有任何用途 ⇒ 3 位 pred 是纯损失。代价:这两条指令不可谓词化 |
| D17 | LAUNCH 带 `flags`,CP 连续打包并校验 barrier | 让"`bar.sync` 要求 num_warps ≤ 4 且同 SM"从口头约定变成可强制的分发前置条件;否则多 SM 的 barrier 会静默死锁。代价:LAUNCH 多一个字段、CP 多一条校验 |
| D18 | warp 启动时寄存器与谓词清零 | 让"屏蔽 lane 参与运算"的垃圾值确定化,参考模型才能逐位对齐。代价:launch 时清寄存器堆(或每 lane 一位 valid) |
| D19 | `ipdom` 独占 opcode `1010111`(RV custom-0 槽),不再与 `bar.sync`/`exit`/`tmov`/`wmov` 共用 `0101011` | 共用时 funct3 既要选指令、又落在 `ipdom` 立即数的 `[14:12]` 里 —— **两者互斥**:按 funct3 译码则 imm20 低 3 位必须为 0,收敛点只能落在 32B 对齐地址,文档里 6 处 `ipdom` 全部不可译码。`ipdom` 写的是 warp 级的 recov 寄存器,和写 `rd` 的 `tmov`/`wmov` 本就不是同类。代价:多占 1 个 opcode(还有 118 个空位),换来 U 型格式统一为 imm20 |
| D20 | **GEMM 不进 shader ISA,走独立矩阵引擎** | 设计点不匹配:SIMT 核实测 3.10 个发射槽/MAC ⇒ 2 SM 峰值约 1.0 GMAC/s(FP32);而矩阵引擎按 16×16 INT8 脉动阵列估算可达 51.2 GMAC/s,差 ~50×,而且引擎自包含(不改 ISA、验证方式是"与 numpy 全对")。反观"往核内加矩阵指令":同样的峰值要同时动寄存器堆、共享内存读口数、调度、分歧语义四样东西,还要新增"warp 协作指令必须均匀执行"的语义约束,集成与验证成本高一个量级。目标内核 clear/gouraud/relu 与 2D 引擎都不需要矩阵运算 —— matmul 的定位是 **ISA 验收**,不是性能目标。**何时重新考虑**:若 INT8 量化推理成为主负载,按扩展路线先做多字访存,再点积/mma,而不是一步上 warp mma |

## 2. 跨文档冲突与处置(历史)

早期几份文档对同一件事各写一套。下表记录冲突与最终归属,结论已写进正文,**保留在此仅为存档**。

| # | 冲突 | 各方说法 | 处置 |
|---|---|---|---|
| 1 | MMIO 基址 | 计划文档 `0x0000_0000`;CMDS v0.1 建议 `0x4000_0000` | 采用 `0x0000_0000`,现由 SPEC §2 确认为地址权威 |
| 2 | 命令长度 | 计划文档"固定 64B 一条";CMDS v0.1 变长 `length_words` | **保留变长格式**(自描述、便于扩展),但要求驱动把每条命令填充到 64B 边界 ⇒ 环指针运算仍然简单 |
| 3 | 帧缓冲基址 | 计划文档"基址/尺寸/格式可配置";CMDS v0.1 `FB_BASE` 固定只读 | `FB_BASE` 改为 R/W,复位值 `0x1000_0000`;**尺寸/格式归 2D 引擎寄存器**(GFX §3) |
| 4 | `0x0200_0000` 区用途 | 计划文档"内核代码 + 常量内存";ISA 常量区基址固定 `0x0200_0000` | 定义子布局:常量块占前 4KB,镜像自 `+0x1000` 起 |
| 5 | 矩阵引擎命令 | 计划文档有 GEMM 引擎与分块命令;CMDS v0.1 无 GEMM opcode | 预留 `0x18–0x1F`,v0.3 定义 `0x18 = GEMM` |
| 6 | 顶点格式 | 计划文档 `{x, y(s16.15), r, g, b, a, u, v)}`(定点);ISA 示例内核用 `6×f32 = 24B` | **由 GFX §2.1 定为 `6×f32 = 24B`**(AoS),定点顶点格式否决;CMDS 侧只影响顶点缓冲的地址与大小计算 |
| 7 | 2D 引擎状态/错误在哪看 | CMDS 原有 `IRQ_2D_DONE`,但没有寄存器能读出"引擎忙/完成/出错" | `2D_STATUS`(0x68)/`2D_ERROR`(0x6C)落在 CP MMIO,与 `GEMM_STATUS`/`GEMM_ERROR` 同约定;`CP_ERROR` 增 `8 = ENGINE_FAULT` |

## 3. 被否决的做法(不要重新提议)

| 做法 | 否决理由 |
|---|---|
| 固定 64B 命令格式 | 变长格式更省带宽且自描述;用"驱动补齐到 64B"同时拿到环指针算术的简单性 |
| 定点顶点(`s16.15`) | 文档必须与已跑通的内核一致(gouraud 用 24B FP32 顶点);定点化把格式转换成本塞进通用核,而它属于固定功能单元 |
| 把常用 MMIO 寄存器另存一份副本在 CP 内 | 副本必然带来"host 改了而 CP 读旧值"这类并发 bug。正确做法是**一份状态 + 两个访问口**(内部状态机直接读写,外部经 AXI4-Lite 从口访问同一份),见 SPEC §3.1 契约 5–7 |
| 往 shader ISA 里加矩阵指令 | 见 D20:同样的峰值要同时动寄存器堆、共享内存读口数、调度与分歧语义;正确答案是独立矩阵引擎 |
| 用 `CMD_HEAD` 的命令流写路径做"异常恢复" | 命令流在 ERROR 态本来就执行不了;`CMD_HEAD` 只允许 host 直写(命令流写它报 `CMD_ERROR`),恢复走 `CP_RESET` |
| 微码化重写 CP 状态机 | 5 bit 状态编码只值 5 个触发器;少状态 = 多 flag,面积不减,还会丢掉可调试性与验证基线 |

## 5. 文档约定(给维护者)

1. 手册只写**当前成立的规则**;决策过程写在本文件。
2. 每条规则引到具体章节(`§N.M`),交叉引用必须指向**当前存在的**编号。
3. 文档与实现必须同时改;改动摘要进各文档的"变更记录"表(编号唯一递增)。
4. 反引号里的仓库路径必须真实存在;不得把已删除的计划文档当活跃权威引用。
