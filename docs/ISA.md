## 1. 设计目标与总体原则

本指令集服务于 SimpleGPU 的可编程 SIMT shader 核,承担三类负载:

1. **顶点变换**(2D 仿射变换,FP32)
2. **通用并行计算**(向量运算、矩阵分块等)
3. 未来扩展: 像素着色、通用计算内核

设计原则:

| 原则 | 说明 |
|---|---|
| RISC-V 风格 | 32 位定长编码、r0 恒零、lui+addi 构造大常量 —— 直接复用 RV32IMF |
| **语义兼容 ≠ 二进制兼容** | FP32 运算、除法余数、比较的**语义**与 RV32F/RV32M 一致,但**编码不兼容 RV** —— 统一 pred 字段与 R4 形式占用了 RV 的位域(§4)。RTL 复用的是运算逻辑,不是译码器 |
| SIMT 语义 | 每 lane 独立寄存器/谓词,共享 PC;分歧用硬件栈处理(见 §2) |
| 最小够用 | 指令集由目标内核反推而来(§7 的 clear/gouraud/matmul 三个),不设计用不上的指令;另加一个发散内核 abs 专门验证 SIMT 栈 —— 反推保证"没有多余指令",验证内核保证"没有漏掉机制" |
| FP 复用 | FP32 算术语义与 RV32F 一致,fma 单次舍入,datapath 逻辑直接复用现有 FPU |
| **可诊断优于未定义** | 硬件能廉价检测的非法情形(栈溢出、未对齐访存、非法指令、barrier 用错)一律置错误标志并停机,不写成"未定义行为" —— 单人项目的调试成本远高于几个比较器(§2.6、D14) |

**指令总数: 48 条 + 5 条伪指令**,分 9 类(§5、§6)。精确分布(供 RTL 译码表逐条核对):

| 类别 | 条数 | 位置 |
|---|---|---|
| 整数 ALU(含 RV32M 的 mul/div/rem) | 15 | §5.1 |
| FP32 算术 | 7 | §5.2 |
| 融合乘加(4 条 FP fma + 1 条整数 imad) | 5 | §5.3 |
| 比较 → 谓词(setp,18 种编码) | 1 | §5.4 |
| 立即数 ALU(addi/slli/slti/sltiu/xori/srli/srai/ori/andi) | 9 | §5.5 |
| 大立即数(lui) | 1 | §5.5 |
| 访存(ld.g/ld.s/st.g/st.s) | 4 | §5.6 |
| 控制与特殊(ipdom/bar.sync/exit/tmov/wmov) | 5 | §5.7 |
| 分支(br.simt) | 1 | §5.8 |
| **合计** | **48** | 另有 `mov`/`not`/`neg`/`nop`/`j` 五条伪指令(§5.9) |

## 2. 执行模型 (SIMT)

### 2.1 基本概念

| 概念 | 定义 |
|---|---|
| **lane (线程)** | 最小执行单元。每个 lane 有独立的 32×32b 通用寄存器、4×1b 谓词 |
| **warp** | 8 个 lane 组成,共享一个 PC。**本设计的 warp 宽度 = 8**(决策记录 D1) |
| **SM** | 每 SM 4 个 warp;共 2 个 SM |
| **active mask** | 8b 硬件状态(每 lane 1b),标记当前指令实际生效的 lane。由 SIMT 栈自动维护 |
| **kernel** | 一次 LAUNCH 启动的执行单元 = 一组 warp |

**有效执行条件:** lane 执行一条指令 ⟺ (lane ∈ active_mask) ∧ (谓词为真,若有谓词)。即:

```
effective_mask = active_mask & pred_mask
```

其中 `pred_mask` = **该指令谓词字段决定的 lane 掩码**: 取 `[27:26]` 选的谓词(`00=p0`…`11=p3`),若 `[28]=inv` 则该 lane 取反(§4.1)。没有谓词字段的三类指令(`fma`、`lui`、`ipdom`)令 `pred_mask = 全 1`(§4.2)。

### 2.2 启动模型 (LAUNCH)

```
LAUNCH {kernel_pc, num_warps, flags}
```

- `num_warps` ≤ 8,且 **所有 warp 全部常驻**(不做多波次调度 —— 决策记录 D6)
- LAUNCH 由 **CP(命令处理器:负责取命令、分发到各引擎、跟踪完成;其寄存器与命令编码见 CMDS.md)** 执行;本文档只规定 CP 必须遵守的约束
- `flags[0] = USES_BARRIER`: 由汇编器从内核元数据写入(内核里出现过 `bar.sync` 就置位)
- 初版内核代码由 **CP 在启动前预加载到 SM 本地指令 SRAM**(16KB/SM),不设指令缓存
- 每个 warp 获得全局编号 `wid` = 0..num_warps-1,可由 `wmov` 读取
- kernel 结束条件: 所有 warp 执行 `exit`
- **内核参数一律通过常量内存传递**(全局地址 0x0200_0000 区,用 ld.g 读取)—— 无寄存器 ABI 负担(决策记录 D8)

**warp 放置规则(硬性 —— bar.sync 可实现的前提):**

- CP **连续打包**: 先填满 SM0 的 4 个 warp 槽,再填 SM1。于是
  - `num_warps ≤ 4` → 必然单 SM 常驻
  - `num_warps ≥ 5` → 必然跨 SM
- 若 `flags` 声明 USES_BARRIER 而 `num_warps ≥ 5` → **CP 必须在分发前拒绝(置 LAUNCH_REJECT,§2.6)**,不得静默执行:静默执行的结果是各 SM 的 barrier 各自等自己那半边,永久死锁且难以定位
- 这一条补上了 v0.1 的缺口:原文要求"用 bar.sync 的内核 num_warps ≤ 4",但没有任何机制保证这 4 个 warp 真的落在同一个 SM 上

**指令 SRAM 预算:** 16KB/SM = **4096 条指令**(PC 为字节地址、4B 对齐)。这是内核**静态代码**的硬上限;`ipdom`/`br.simt` 的 PC 相对范围(±2MB / ±8MB,见 §4.2)远大于它,所以不存在"代码大到跳不过去"的情况。

**warp 在本 SM 内的槽号:** CP 连续打包意味着 SM0 拿到 `wid` 0..3、SM1 拿到 4..7,所以"本 SM 内第几个 warp" = **`wid mod 4`**。SM 内部的位图/表(如 `warp_alive`)都按这个槽号索引,不要直接用全局 `wid`。

**kernel 结束的判定:** 每 SM 维护 `warp_alive[3:0]` 位图(按槽号 `wid mod 4`,`bar.sync` 只用 ≤ 4 warp 的内核不会踩到跨 SM 的索引问题)。warp 执行 `exit` 时先冲刷自己的写缓冲,再清 `warp_alive[wid mod 4]`;位图全 0 → 置 `sm_done`(MMIO 可读)。CP 等所有涉及到的 SM 的 `sm_done` 齐了才放行后续命令。详见 §2.5。

### 2.3 分歧与收敛 (divergence & reconvergence)

GPU 与 CPU 最本质的区别。本设计采用 **"显式 IPDOM + 硬件 SIMT 栈"**: 收敛点由汇编器/编译器用 `ipdom` 显式给出,硬件不做收敛推断、不做分支预测(D10)。

#### 2.3.1 br.simt 的三种情形(一律按 effective_mask 判定)

| 情形 | 条件 | 硬件动作 | 代价 |
|---|---|---|---|
| 均匀不跳 | 无 lane 满足 | PC ← PC+4,不动栈 | 0 |
| 均匀跳转 | 全部 lane 满足 | PC ← label,不动栈 | 0(与普通跳转完全相同) |
| **发散** | 部分 lane 满足 | 压栈(§2.3.2),active_mask ← 跳转 lane 集合,PC ← label | 1 次压栈 |

> 前两种合称**均匀分支**。内核应尽量生成均匀分支(§7 的四个内核里,循环控制全部由全体 lane 相同的标量计数器驱动),这样分支不付压栈与切 mask 的代价 —— 注意"不付栈代价"不等于"零指令": 按 §5.8 的规则,每条无法静态证明均匀的条件分支前仍有一条 `ipdom`(§8.1)。

#### 2.3.2 栈帧内容

| 字段 | 位宽 | 含义 |
|---|---|---|
| `recov_pc` | 32b | 收敛点地址(来自 `ipdom`,§5.7) |
| `fall_pc` | 32b | 分支指令的 PC+4 —— **未跳转 lane 继续执行的地址**(具体是 then 块还是 else 块入口,取决于汇编器把哪一块放在 fall-through 位置) |
| `mask_full` | 8b | 发散前的 active_mask |
| `mask_pending` | 8b | 尚未执行的 lane 集合 = 发散前的 active_mask & ~(跳转 lane 集合) |
| `pending` | 1b | 是否还有一条路径未完成 |

每帧 11B,硬件按 3×32b = 12B/帧打平 ⇒ **8 深栈 = 96B/warp**(每 SM 4 warp 共 384B,可忽略)。

> **为什么 v0.1 的 `{recov_pc, mask, pending}` 不够**(两个互相独立的原因):
> 1. **缺 `fall_pc`**: taken 路径先跑完时,硬件要"重定向到 fall-through 地址",而该地址并没有存在帧里。单层时还能从当前指令推出来,嵌套之后无法恢复 —— 必须显式保存。
> 2. **缺"未执行 lane 集合"**: 表面上未跳转 lane = `mask_full & ~(谓词为真的 lane)`,但 **taken 路径里的 `setp` 会改写谓词**(谓词是 lane 私有状态、不随栈保存),等要切换路径时谓词已经变了,反推不出来。压栈时必须把两个 lane 集合都存下。

#### 2.3.3 路径推进规则(精确到 PC 比较)

1. **发散**: 压栈(字段如上);`active_mask ← mask_full & ~mask_pending`,PC ← label。
2. **路径完成判据: 栈非空 且 PC == 栈顶 `recov_pc`**(只比 PC、不比 mask —— 这正是"immediate post-dominator"的含义)。
3. 路径完成时按 `pending` 分支:
   - `pending = 1`(第二条路径到达收敛点): **弹栈**,`active_mask ← mask_full`,PC 保持 `recov_pc` ⇒ recov_pc 处的指令以**完整 mask 执行一次**。
   - `pending = 0`(taken 路径到达收敛点): 若 `fall_pc == recov_pc`(未跳转路径是空块,例如无 else 的 if),则第二条路径其实也已经在收敛点 ⇒ 直接弹栈、`active_mask ← mask_full`、PC 保持 `recov_pc`;否则 `pending ← 1`、`active_mask ← mask_pending`、`PC ← fall_pc`,**且此刻不执行 recov_pc 处的指令**。
     > 这条空路径特例**不是正确性要求,而是省一拍的实现建议**: 照常切换(`PC ← fall_pc`,而它恰好就是 recov_pc)也能得到相同的架构结果,只是多花一拍去"切换到一条已经在收敛点的路径"。`sim/simt_stack_check.py` 用开/关特例两种实现跑同一段无 else 的代码,验证结果完全一致、且恰好差 1 个周期。
4. 嵌套发散各自压自己的帧、LIFO 处理;**taken 路径恒先执行** ⇒ 同一内核的指令执行顺序是确定的(便于 RTL 与 golden model 逐指令对齐)。

#### 2.3.4 编译器侧的两条收尾约定

- taken 路径若不在 recov_pc 处自然结束,必须显式 `j recov_pc`(见下面示例的 `j end`);否则会一路顺序执行掉进 else 块。
- **发散块里的路径不得"跳过"自己的收敛点**(例如从 if 内部直接 `j` 到 if 之外的目标): 这条路径永远走不到 recov_pc,pending 永不归零,之后某处 PC 恰好等于 recov_pc 就会触发错误的路径切换。要跳出去,必须先把两条路径都汇到 recov_pc,再由 recov_pc 处的代码跳转 —— 由汇编器/编译器保证(需要 convergence barrier 的做法见 §10)。

**栈深与均匀分支(与上面两条独立):**

- 嵌套发散(if 里套 if)由栈深度 8 支持;**压栈时栈已满 = SIMT_OVF 架构错误**(§2.6),不是未定义行为
- **均匀分支不压栈**(§2.3.1 的前两种情形)—— 编译器应优先构造均匀分支;`j label`(@p0)恒为均匀分支,不需要收敛点(§5.9)

**典型 if/else 编译模式**(注意这里的谓词是"取反"用法: `p1` 为真的 lane 是 `r1 <= r2` 的 lane):

```
; if (r1 > r2) r3 = 1;  else r3 = 2;
        setp.le p1, r1, r2        ; p1 = (r1 <= r2) 的 lane
        ipdom end                 ; recov_pc = end(汇编器自动生成,见附录 A)
        br.simt else, end         ; p1 为真的 lane(taken)跳 else;其余落进 then 块
        addi r3, r0, 1            ; then 路径 = 未跳转 lane(r1 > r2 的 lane)
        j end                     ; 必须: 让 then 路径抵达 recov_pc
else:
        addi r3, r0, 2            ; else 路径 = taken lane(r1 <= r2 的 lane)
end:                              ; 两路径会合,完整 mask 继续(此处的指令只执行一次)
```

> **按 §2.3.3 走一遍**(顺序容易搞反,所以逐条写明):
> 1. `br.simt` 处部分 lane 满足 ⇒ 压帧 `{recov_pc = end, fall_pc = br.simt 的下一条 = then 块入口, mask_full = 全 mask, mask_pending = r1>r2 的 lane(未跳转者), pending = 0}`。
> 2. `active_mask ←` **taken lane(r1 ≤ r2)**,PC ← `else` ⇒ 先执行 `addi r3, r0, 2`。**注意 taken 路径在这个例子里是 else 块**,因为谓词写成了取反形式。
> 3. else 块顺序落到 `end` == recov_pc ⇒ `pending = 0` 且 `fall_pc != recov_pc` ⇒ `pending ← 1`、`active_mask ← mask_pending(r1 > r2 的 lane)`、`PC ← fall_pc`(then 块入口),**此时不执行 `end`**。
> 4. then 块执行 `addi r3, r0, 1`,再 `j end` ⇒ PC = `end` == recov_pc ⇒ `pending = 1` ⇒ **弹栈**、`active_mask ← 全 mask`、PC 保持 `end` ⇒ `end` 处以完整 mask 执行一次。

语法: `br.simt label[, reconv]` —— **`reconv` 默认值(PC+4)只对可证明均匀的分支合法**: 一旦发散,recov_pc = PC+4 意味着"收敛点就是未跳转路径的入口",taken 路径将无法抵达。因此汇编器对无法证明均匀的 `br.simt` **必须要求显式 reconv**(否则报汇编错误),并自动在它前面生成 `ipdom`(附录 A)。

> 这套规则已经实现为可执行检查: **`sim/simt_stack_check.py`** —— 它把 §2.3.3 逐条写成状态机,然后在 §2.3.4 的 if/else、无 else 的空路径、§7.4 的 abs(混合符号/全正/全负)上验证"每 lane 结果正确、收敛点只以完整 mask 执行一次、taken 路径先执行、均匀分支不压栈"。**分歧是这套 ISA 里最容易写错的部分(PLAN 的 Phase 3c),先让 Python 版本跑通再写 SystemVerilog,RTL 才有对照物** —— 这也是 §7.4 存在的意义。

### 2.4 barrier 语义

```
bar.sync
```

- **同步范围: 单 SM 内、本 kernel 的全部 warp** —— 由 §2.2 的放置规则保证(声明 USES_BARRIER 的 kernel 必须 `num_warps ≤ 4`,否则 LAUNCH 被 CP 拒绝)
- 附带内存栅栏: 该 warp 此前的 ld/st(shared 与 global)对 bar 放行后的所有 lane 可见
- 单实例 barrier(无 barrier ID);所有 warp 必须执行**相同次数**的 bar.sync
- **实现(每 SM 一套 `{arrived_count, generation}`)**: warp 抵达 bar.sync 时 ① 冲刷自己的 ld/st ② `arrived_count++` ③ 该 warp 挂起并被调度器记为 stall(让出分派,由其他 warp 掩盖延迟)。当 `arrived_count == 本 kernel 在该 SM 的常驻 warp 数` 时清零、`generation++`、释放本 SM 全部挂起 warp。单实例 barrier 的红利: **不需要 per-warp 到达位图**,一个计数器即可(代价见 D7: 无法支持"部分 warp 先同步"的命名 barrier)
- **发散路径中执行 bar.sync = 架构错误**(不是未定义行为): 硬件在 bar.sync 处检查 `active_mask == 8'hFF` 且 SIMT 栈为空,不满足则置 BAR_DIVERGENT(§2.6)并停止该 SM。理由: 死锁比报错难查一个数量级,而这个检查只需要一个比较器
- 同理,`num_warps` 与 `flags` 冲突由 CP 侧拒绝(§2.2)

### 2.5 结束语义

```
exit
```

- **warp 级指令,必须无谓词**(@p0);不允许部分 lane 提前退出(决策记录 D5)
- 附带全局内存栅栏: 该 warp 此前的所有 st.g 在 exit 之后全局可见 —— **这是 kernel 完成信号正确性的基础**
- **完成信号的实现**: 每 SM 维护 `warp_alive[3:0]`(按槽号 `wid mod 4` 索引,§2.2)。exit 先等自己的写缓冲(write-combine buffer,§8 内存子系统里的一级:全局写先入缓冲,容量若干项)冲刷完,再清 `warp_alive[wid mod 4]`;位图全 0 → 置 `sm_done`(MMIO 可读)。CP 等到全部涉及的 SM 的 `sm_done` 齐了,才释放依赖该 kernel 的信号量、才允许后续命令(如 2D 引擎读取顶点输出缓冲)执行
- **不得用"指令发射完毕"代替 exit**: 发射完毕不代表 st.g 已落到内存,那样 2D 引擎会读到未落盘的顶点 —— 这正是必须由 exit 携带栅栏的原因
- **错误状态不算完成**: 任一 SM 处于 §2.6 的错误态时,CP 视该 kernel 失败,不释放信号量(依赖它的命令不执行),避免"带着错误数据继续跑完整帧"

### 2.6 架构错误(architectural errors)

**原则: 能用一个比较器换来的"报错即定位"一律换取**(D14)。下表每一行都必须由 RTL 实现,并在参考模型中用同样的条件判定。

| 错误 | 触发条件 | 检测成本 |
|---|---|---|
| ILLEGAL_INSTR | 未定义 opcode / 保留字段非 0 / 非法 funct 组合 | 译码顺带 |
| SIMT_OVF | 压栈时栈深已达 8 | 计数器比较 |
| BAD_ALIGN | ld/st 地址 `[1:0] != 0`(§3.2) | 1 个比较器 |
| BAR_DIVERGENT | bar.sync 时 `active_mask != 8'hFF` 或 SIMT 栈非空 | 1 个比较器 |
| ERR_NO_RECOV | 发散时 recov 有效位为 0(汇编器漏生成 `ipdom`,§5.7) | 1 位比较 |
| LAUNCH_REJECT | `flags.USES_BARRIER` 且 `num_warps ≥ 5`(§2.2) | CP 侧 |

- 一旦置位: 该 SM **停止取指并把错误码写进 MMIO 状态寄存器**(位定义由 CMDS.md 给出),由 host 读取并复位;绝不静默继续
- 错误状态对 CP 的意义见 §2.5(该 kernel 视为失败)
- 停机而不是"尽力而为"的理由: 教学项目的调试预算最贵,而安静的错误数据最终会表现为"帧缓冲里几个像素不对",定位成本是几十倍

## 3. 编程模型

### 3.1 寄存器

| 资源 | 每 lane | 说明 |
|---|---|---|
| 通用寄存器 r0..r31 | 32×32b | r0 恒为 0(写丢弃);无 ABI 约定 |
| 谓词 p0..p3 | 4×1b | p0 恒真、不可写;p1..p3 由 setp 写入 |

要点(v0.1 中只在示例里隐含出现的约定,v0.2 写明):

- **寄存器堆是统一的**: INT32 与 FP32 值共用 r0..r31(与 RV32F 一样用整数寄存器号寻址),**没有独立 FP 寄存器堆、没有 fp↔int 搬移指令** —— 这是复用 RV32IMF 数据通路的直接结果,也让 `ld.g` 可以直接把 FP32 位型装进寄存器(§7.2)
- **没有 call/ret、没有栈指针/返回地址寄存器**: 内核是单函数、不可递归(§3.2),32 个寄存器全部可用于计算。这也是 §7.3 的 matmul 能把 30 个通用寄存器都排上用场(只剩 r4 空闲)的原因
- **warp 启动时寄存器与谓词清零**: 32 个通用寄存器全部为 0,p0 = 真、p1..p3 = 假。这不是可以留白的细节 —— 发散时屏蔽 lane 仍会参与**没有谓词字段的指令**(如 `fma`)的计算,读到的就是这些初值;把初值定死,RTL 与 Python 参考模型才能逐位对齐(§7.2 的"垃圾值无害"论证依赖这一条,见 D18)
- **谓词是 lane 私有状态,不随 SIMT 栈保存/恢复**: 发散时各 lane 只在自己执行的那条路径上被 `setp` 更新,收敛后不同 lane 的同一谓词可能不同 —— 这是 lane 级语义,不是不一致(但正因为它不保存,§2.3.2 的栈帧才必须显式存两个 lane 集合)
- `r0` 写入被静默丢弃(包括 `lui r0`);`p0` 不可写,`@!p0` = 该指令对所有 lane 关闭(§5.10)

特殊值(经指令读入寄存器):

| 指令 | 值 |
|---|---|
| `tmov rd, tid` | lane 编号 (0..7) |
| `wmov rd, wid` | warp 全局编号 (0..num_warps-1) |

### 3.2 内存空间

| 空间 | 指令 | 地址 | 说明 |
|---|---|---|---|
| 全局 | ld.g / st.g | 32b 物理地址 | 帧缓冲、数据、常量区、内核代码(预加载后) |
| 共享 | ld.s / st.s | 独立地址空间,每 SM 16KB (0x0000..0x3FFF) | SM 内跨 lane/warp 通信 |

- **全部为 32 位字访问,无字节/半字**(决策记录 D3)。地址必须 4B 对齐,**未对齐 = BAD_ALIGN 架构错误**(§2.6),不是未定义行为
- **无本地内存/栈**: 寄存器即全部本地状态,不可递归(因此也不需要栈指针)
- 全局空间**无缓存**: 每次 ld.g/st.g 都要过 SM 内合并器 + 共享的 AXI4 主口 ⇒ **合并质量直接决定性能**,内核写法(相邻 lane 访问相邻字)是主要优化手段,而不是靠 cache
- **共享内存是 SM 内存储**: 跨 warp 的读写必须靠 `bar.sync` 建立可见性(§2.4);同 warp 内 lane 之间也需要 bar.sync 或约定不发生竞争
- **共享 SRAM 与指令 SRAM 是两块独立存储**,各 16KB(§8);不要混淆
- **合并器行为**(warp 级访存指令):

| 情形 | 硬件动作 | 代价 |
|---|---|---|
| 8 个 lane 地址连续 | 合并为 1 次 32B burst | 1 次请求(理想情况,内核应对齐这个目标) |
| 8 个 lane 地址相同(常量加载) | 1 次请求,广播回所有 lane | 1 次请求(§7 的常量读、§7.3 的共享广播都靠它) |
| 部分 lane 被谓词/active mask 屏蔽 | 对剩余活跃 lane 的连续段做子 burst | 请求数 = 连续段数 |
| 地址分散 | 逐请求发出 | 最多 8 次(正确,仅慢) |

- **共享内存 bank**: 8 bank × 32b,bank = addr[4:2]。所有 lane 同地址 = 广播(1 周期);异地址同 bank = 冲突,串行化(正确,仅慢)。§7.3 的"lane 各写一列 + 全体广播读"布局就是为零冲突设计的

### 3.3 数值格式

| 类型 | 说明 |
|---|---|
| FP32 | IEEE-754 单精度。fadd/fsub/fmul/fma 舍入模式 round-to-nearest-even;fma 单次舍入;**与 RV32F 语义一致,直接复用现有 FPU** |
| fmin/fmax | 与 RV32F 一致(NaN 处理: 一个操作数为 NaN 时返回另一操作数) |
| 次正规数 | **不做 flush-to-zero**,与 RV32F 一致(次正规数按 IEEE 计算)。这条要写死,否则 RTL 与参考模型会在极小值上永远对不齐 |
| f2i | FP32 → INT32,**向零舍入**;输入为 NaN 或超出 INT32 范围时**饱和**(NaN → 0,正溢出 → 0x7FFF_FFFF,负溢出 → 0x8000_0000),与 RV32F 的 `fcvt.w.s` 一致 —— v0.1 未定义该情形 |
| i2f | INT32 → FP32,RNE(按最近偶数舍入;绝对值 ≤ 2^24 时精确) |
| INT32 | 有符号/无符号算术,div/rem 与 RV32M 一致(除零: div = 全 1、rem = 被除数等) |
| **没有的运算** | **无 FP 除法、无开方、无 FP64、无 FP16**。fdiv/fsqrt 在 RV32F 里是最贵的单元,而 §7 的目标内核都不需要;需要倒数/归一化时改用定点(交 2D 引擎)或多项式近似(§10) |
| 异常 | **全部非 trapping** —— 不产生异常、不设 FP 陷阱标志位。这是谓词化 `fma` 安全性的前提(D4): 允许对不活跃 lane 算出垃圾值 |
| 边界一致性 | 上述所有"边界行为"必须与 Python golden model 使用同一套规则(尤其 NaN、次正规、f2i 饱和),否则 PLAN.md §11 的分层回归会在边界用例上长期红 |

> 2D 引擎内部使用定点数 s16.15,但那是 GFX.md 的领域。**shader 核只做 FP32**,顶点输出经内存交给 2D 引擎转换。

### 3.4 常量约定

内核经 LAUNCH 启动后,自行从常量区(0x0200_0000,由驱动写入)读取参数,例如:

```
[0]=数据基址 [4]=元素个数 [8]=步长 ...   ← 内核与驱动的约定,文档化为内核注释
```

## 4. 指令格式

**先看字段预算(为什么长这样):** 32 位里必须放下 `opcode[6:0]`、统一谓词字段 `pred[3b]`(这就是 SIMT 每指令谓词化的代价)、目的寄存器 `rd[5b]`,只剩 **17 位**留给功能码与立即数。本文档里所有"看起来奇怪"的地方都源自这个预算。

- **pred 恒在 bits[28:26]**: `[28]=inv(取反)`,`[27:26]=psel(00=p0, 01=p1, 10=p2, 11=p3)`。位置恒定 ⇒ "是否谓词化、是否取反"只需看固定的三位,译码不必按格式分派
- **两处例外(指令没有谓词字段)**,理由各自成立:
  - `fma` 家族(R4 型): 4 个寄存器字段 + opcode 已把 32 位占满(D4)
  - `lui` / `ipdom`(U 型): 立即数要覆盖整个 4KB 对齐地址空间与代码空间,把 3 位 pred 让给立即数才够(§4.2)
- **保留位必须为 0**: 违反 = ILLEGAL_INSTR(§2.6),不算未定义行为

### 4.1 指令格式(共七种:R / I / S / U / B / R4 / setp)

```
┌─R 型 (opcode 0110011)──────────────────────────────────┐
│31..29│28..26│25│24..20│19..15│14..12│11..7│6..0│
│funct4[3:1]│ pred │funct4[0]│ rs2 │ rs1 │funct3│ rd │op │
└────────────────────────────────────────────────────────┘
  funct3=000 → 整数 ALU(funct4 共 16 槽,用 15,留 1 个给扩展)
  funct3=001 → FP32  (funct4 共 16 槽,用 7)

┌─I 型 (opcode 0010011 立即数 ALU / 0000011 载入)────────┐
│31..29│28..26│25..20│19..15│14..12│11..7│6..0│
│imm[8:6]│ pred │imm[5:0]│ rs1 │funct3│ rd │op │
└────────────────────────────────────────────────────────┘
  imm9 = sext({imm[8:6], imm[5:0]}) → −256..+255

┌─S 型 (opcode 0100011 存储)─────────────────────────────┐
│31..29│28..26│25│24..20│19..15│14..12│11..7│6..0│
│imm[8:6]│ pred │imm[5]│ rs2 │ rs1 │funct3│imm[4:0]│op │
└────────────────────────────────────────────────────────┘
  imm9 同 I 型;rs2 = 要写入内存的数据

┌─U 型 (opcode 0110111 lui / 1010111 ipdom)──────────────┐
│31..26 (6b)│25..12 (14b)│11..7│6..0│
│        imm[19:0]        │ rd │op │        ← 无 pred 字段
└────────────────────────────────────────────────────────┘
  lui:   rd = sext(imm20) << 12
  ipdom: recov_pc = PC + sext(imm20) << 2

┌─B 型 (opcode 1100011 br.simt)──────────────────────────┐
│31..29│28..26│        25..7 (19b)         │6..0│
│imm[21:19]│ pred │        imm[18:0]         │op │  ← rd/funct3 位并入立即数
└────────────────────────────────────────────────────────┘
  target = PC + sext(imm22) << 2

┌─R4 型 (opcode 1010011,无 pred 字段)────────────────────┐
│31..27│26..25│24..20│19..15│14..12│11..7│6..0│
│ rs3 │funct2│ rs2 │ rs1 │funct3│ rd │op │
└────────────────────────────────────────────────────────┘
  funct3=000 → FP32 fma 家族(funct2 选 4 条)
  funct3=001 → 整数 imad(funct2 必须 00)

┌─setp (opcode 0001011)──────────────────────────────────┐
│31..29│28..26│25│24..20│19..15│14..12│11..7│6..0│
│ cond │ pred │ 0 │ rs2 │ rs1 │family│pdest│op │
└────────────────────────────────────────────────────────┘
  cond[31:29]:   000=eq 001=ne 010=lt 011=ge 100=le 101=gt(110/111 保留)
  family[14:12]: 000=有符号整数 001=无符号整数 010=FP32(其余保留)
  pdest[11:7]:   00001=p1 00010=p2 00011=p3(rd[4:2] 必须为 0,其余值 ILLEGAL_INSTR)
```

> **v0.1 的 setp 图有两处位域重复占用**: `family[29:27]` 与 `pred[28:26]` 在 bit 28/27 上冲突;`op[25:20]` 与 `rs2[24:20]` 在 bit 24..20 上冲突 —— 这是图纸错误,该编码无法译码。v0.2 的修法是**把新字段放进 R 型本来就空着的位置**: `cond` 用 funct4 的高三位 `[31:29]`、`family` 用 `funct3[14:12]`、`pdest` 用 `rd[11:7]`。于是 setp 与 R 型的字段位置完全同构,`pred`/`rs1`/`rs2` 位置不变,译码器只需一个"opcode=0001011"的分支。

### 4.2 立即数范围与"lui 为什么没有谓词"

| 用法 | 位宽 | 范围 | 用途 |
|---|---|---|---|
| I/S 型 imm9 | 9b 有符号 | −256..+255 | 结构体内小偏移、指针步进(±255B 足够覆盖 24B 顶点、32B 共享 tile 槽) |
| U 型 lui | 20b 有符号,`<<12` | −0x8000_0000 .. +0x7FFF_F000 | **全部 4KB 对齐的 32 位物理地址** |
| U 型 ipdom | 20b 有符号,`<<2`,PC 相对 | PC ± 2MB | 代码空间只有 16KB(§2.2),富余 128 倍 |
| B 型 br.simt | 22b 有符号,`<<2`,PC 相对 | PC ± 8MB | 同上 |

`lui` 的三个必用常量都能一条指令装出来:`0x0200_0000`(常量区)= `lui rd, 0x2000`、`0x1000_0000`(帧缓冲)= `lui rd, 0x10000`、`0x8000_0000`(DDR)= `sext(−2^19)<<12`。

> **lui 为什么必须放弃谓词字段**: U 型要同时容纳 `rd[5b]` 与立即数,而 32 位减去 opcode 与 rd 只剩 20 位;若保留 3 位 pred,立即数只剩 17 位,`sext(imm17)<<12` 最大到 `0x0FFF_F000` —— **连帧缓冲基址 0x1000_0000 都够不到**,§7 的 `lui r10, 0x10000` 会直接汇编失败。而"条件地装一个常量"在任何内核里都没有用处,所以这 3 位是纯收益。(v0.1 的 U 型图声称 imm22 且同时保留 `funct3` 与 `rd`,同样存在位域重复 —— imm[18:0] 覆盖 [25:7],与 `funct3[14:12]`、`rd[11:7]` 重叠,所以那个 22 位也是实现不了的。)
>
> **br.simt 为什么反而是 22 位**: 它没有 `rd`、也不需要 `funct3`,`[25:7]` 这 19 位可以整块并入立即数(`br.simt` 本来就不需要 rd/funct3,所以这 19 位全部可用)。两条 PC 相对指令范围不同(±8MB vs ±2MB)不影响正确性,两者都远大于代码空间。

### 4.3 三条编码规则(汇编器/编译器必须遵守)

1. **`fma` 的写回粒度是 active_mask,不是谓词**: 由于 FP 运算非 trapping、无副作用,对不活跃 lane 算出垃圾值是安全的(D4)。但反过来说,**需要比 active_mask 更细的条件累加时不能用 fma**(它没有谓词字段,无法逐 lane 关闭): 应改用带谓词的 `fmul` + `fadd`,或把该计算重排进真正的发散分支。这条限制 v0.1 没说,而它正是"谓词化表达式"最容易踩的坑。
2. **移位量的 RV trick**: slli/srli/srai 的移位量 = `imm[4:0]`;srli 与 srai 共用 funct3=101,由 `imm[5]`(0/1)区分;`imm[8:6]` 必须为 0。
3. **非法组合一律 ILLEGAL_INSTR**: R 型 funct3=010..111、setp 的保留 cond/family、U 型的保留位、`fma` 的非法 funct2 等。

### 5.3 融合乘加(R4 型,opcode 1010011,无谓词)

**funct3 = 000 —— FP32**(舍入: 单次,与 RV32F 的 fmadd 家族语义一致):

| 指令 | funct2 | 语义 |
|---|---|---|
| `fma.f32 rd, rs1, rs2, rs3` | 00 | rd = rs1×rs2 + rs3(单次舍入) |
| `fmsub.f32 rd, rs1, rs2, rs3` | 01 | rd = rs1×rs2 - rs3 |
| `fnmsub.f32 rd, rs1, rs2, rs3` | 10 | rd = -(rs1×rs2) + rs3 |
| `fnmadd.f32 rd, rs1, rs2, rs3` | 11 | rd = -(rs1×rs2) - rs3 |

**funct3 = 001 —— 整数**(funct2 必须为 00):

| 指令 | 语义 |
|---|---|
| `imad rd, rs1, rs2, rs3` | rd = rs1×rs2 + rs3(32 位截断,无舍入概念) |

> **为什么值得多这 1 条指令(D12)**: "基址 + 索引×步长,且乘数已经在寄存器里"这种模式在目标内核里出现 3 次(gouraud 2 次: in/out 指针;matmul 1 次: C 行基址)。写成 `mul`+`add` 是 2 条指令,还要多占一个临时寄存器。硬件上乘法器与加法器本来都有,`imad` 只是把两级串起来,不新增功能单元,面积增量≈0。
> **反例同样重要**: clear 内核故意不用 imad —— 那里的乘数是常量 8/4,单独装进寄存器反而多一条指令,`slli`+`add` 两指令等价 ⇒ imad 的收益来自"乘数已经在寄存器里"的场景(§7.2 的 stride、§7.3 的 N)。这说明加指令也要按数据流判断,不能只看"能省一条"。

### 5.4 比较 → 谓词(setp,opcode 0001011)

`setp.<cond> pdest, rs1, rs2` —— 对 **effective_mask 内的所有 lane** 求值;被谓词屏蔽的 lane 的 pdest **保持原值**(不写)。字段编码见 §4.1: `cond` 在 `[31:29]`、`family` 在 `funct3[14:12]`、`pdest` 在 `rd[11:7]`。

family × cond = **18 种合法编码**:

| cond | 有符号整数(000) | 无符号整数(001) | FP32(010) |
|---|---|---|---|
| eq | `setp.eq` | `setp.eq` | `setp.feq` |
| ne | `setp.ne` | `setp.ne` | `setp.fne` |
| lt | `setp.lt` | `setp.ltu` | `setp.flt` |
| ge | `setp.ge` | `setp.geu` | `setp.fge` |
| le | `setp.le` | `setp.leu` | `setp.fle` |
| gt | `setp.gt` | `setp.gtu` | `setp.fgt` |

- **FP 比较是 IEEE 有序比较**: 任一操作数为 NaN 时 `feq`/`flt`/`fle`/`fge`/`fgt` 全为**假**;**`fne` 定义为 `!feq`**(NaN 时为**真**,等价于 RV32F 的 `feq.s` 再取反)。把这个写死,否则 NaN 路径上 RTL 与参考模型必然分叉
- **v0.1 的表有两处问题**: ① 6 个 op 编码只映射到 4 个条件,于是 fp 列不得不写成 `000100 → setp.fle`,即"op 名(flt)与指令名(fle)对不上";② 完全没有 FP 的 eq/ne,也没有任何家族的 le/gt。v0.2 把 cond 扩到 3 位(6 个条件)后这两个缺口都消失,而**代价为 0** —— `[31:29]` 这三位在 setp 里本来没有别的用途
- **没有 le/gt 时的等价写法**(v0.2 起不再必需,但汇编器可利用): `a <= b` ≡ `setp.ge p, b, a`(交换操作数),`a > b` ≡ `setp.lt p, b, a`
- **谓词化 setp 的一条实用性质**: 被屏蔽 lane 的 pdest 不更新 ⇒ `@p2 setp.lt p1, a, b` 等价于 `p1 = p2 ? (a<b) : p1` —— "条件写入"。在没有 `andp`/`orp`(§10)的情况下,这是拼复合条件的主要手段。v0.1 已有该语义但没写明用途,容易被实现者当作可省的细节丢掉
- pdest 只能是 p1..p3(p0 恒真、不可写,D9);写 p0 或使用保留位 ⇒ ILLEGAL_INSTR(§2.6)

### 5.5 立即数与常量

**I 型立即数 ALU(opcode 0010011)** —— 共 **9 条**指令,落在 **8 个 funct3 槽**(101 由 `imm[5]` 区分 srli/srai):

| 指令 | funct3 | 语义 |
|---|---|---|
| `addi rd, rs1, imm9` | 000 | rd = rs1 + sext(imm9) |
| `slli rd, rs1, shamt` | 001 | 移位量 = imm[4:0],imm[8:5] 必须为 0 |
| `slti rd, rs1, imm9` | 010 | 有符号 |
| `sltiu rd, rs1, imm9` | 011 | 无符号(注意: 立即数先符号扩展再按无符号比较,与 RV 相同,易踩) |
| `xori rd, rs1, imm9` | 100 | |
| `srli rd, rs1, shamt` | 101 | imm[5]=0;imm[8:6] 必须为 0 |
| `srai rd, rs1, shamt` | 101 | imm[5]=1;imm[8:6] 必须为 0 |
| `ori rd, rs1, imm9` | 110 | |
| `andi rd, rs1, imm9` | 111 | |

**大立即数(opcode 0110111):** `lui rd, imm20` → rd = sext(imm20) << 12,**没有谓词字段**(理由见 §4.2)。

- 用途: 装 4KB 对齐的基址 —— 常量区 `0x0200_0000`、帧缓冲 `0x1000_0000`、DDR `0x8000_0000`、共享内存基址。§7 四个内核的所有 `lui` 都属于这一类
- **非 4KB 对齐的常量需要 2~3 条指令**: addi 的立即数只有 9 位,`lui r, hi+1` + `addi r, r, lo-4096` 只覆盖低 12 位落在 [3840, 4095] 的情形,其他情况要 `lui` + `slli` + `ori` 组合。**因此内核不应现算大常量,而应把参数与常量放进常量内存用 `ld.g` 读**(D8)—— v0.1 的附录只说"lui 接受完整 32 位常量,由汇编器拆分",把这条真实成本藏起来了
- 反过来,这也是 9 位立即数(而非 12 位)最实际的代价: 它不影响 §7 的目标内核(偏移都在 ±255B 内),但会惩罚"手工构造位模式"的写法 —— 而常量内存路线正好避开它

### 5.6 访存

| 指令 | opcode | funct3 | 语义 |
|---|---|---|---|
| `ld.g rd, imm9(rs1)` | 0000011 | 000 | rd = 全局[rs1 + imm9] |
| `ld.s rd, imm9(rs1)` | 0000011 | 001 | rd = 共享[rs1 + imm9] |
| `st.g rs2, imm9(rs1)` | 0100011 | 000 | 全局[rs1 + imm9] = rs2 |
| `st.s rs2, imm9(rs1)` | 0100011 | 001 | 共享[rs1 + imm9] = rs2 |

- 地址 = 每 lane 的 rs1 + imm9,其中 **imm9 是字节偏移**(有符号,−256..+255,§4.2),**必须 4B 对齐**(未对齐 = BAD_ALIGN 架构错误,§2.6;v0.1 写的是"未定义",而检测它只需要一个比较器)
- **谓词为假的 lane 不产生访存请求**(不是"请求了但丢弃")—— 这既让尾部屏蔽不会越界访问(§7.2),也直接减少合并器的请求数
- 载入与存储都是 **warp 级**: 8 个 lane 各自给出地址,由合并器按 §3.2 的规则归并
- 没有 `ld.g` 的"立即数偏移超过 9 位"的兜底: 大偏移要先用 `addi`/`imad` 把地址算进寄存器(内核里指针步进的写法就是这个原因)

### 5.7 控制与特殊

| 指令 | opcode | funct3 | 布局 | 说明 |
|---|---|---|---|---|
| `ipdom imm20` | **1010111** | — | U 型(**无谓词**) | `recov_pc ← PC + sext(imm20)<<2`。**只对紧随其后的第一条 br.simt 生效**,用后硬件清"recov 有效位"。汇编器自动生成(附录 A),均匀分支不需要 |
| `bar.sync` | 0101011 | 001 | I 型 | rd/rs1/imm 必须为 0,谓词必须 p0。语义与实现见 §2.4 |
| `exit` | 0101011 | 010 | I 型 | 同上。语义与完成信号实现见 §2.5 |
| `tmov rd, tid` | 0101011 | 011 | I 型 | rd = lane 编号 0..7(rs1 必须 r0) |
| `wmov rd, wid` | 0101011 | 100 | I 型 | rd = warp 全局编号 0..num_warps-1(rs1 必须 r0) |
| — | 0101011 | 000 / 101..111 | — | **保留**(ILLEGAL_INSTR) |

- **为什么 `ipdom` 独占一个 opcode(D19)**: v0.2 早期版本把它和 `bar.sync`/`exit`/`tmov`/`wmov` 一起挤在 `0101011` 里用 funct3 区分,但 `ipdom` 是 U 型、立即数占 `[31:26]+[25:12]` —— 其中 `[14:12]` 正是 funct3 的位置,**"用 funct3 选指令"与"imm20 覆盖到 bit 12"互相排斥**: 按 funct3 译码,imm20 的低 3 位必须为 0,收敛点就只能落在 32B 对齐的地址上,而文档里 6 处 `ipdom` 示例一条都不可译码。修法是让 `ipdom` 独占 opcode `1010111`(RV 的 custom-0 槽,标准 RV 不用它): U 型格式得以统一为 imm20,`0101011` 安心留给 4 条 I 型控制指令。代价是多占 1 个 opcode(还有 118 个空位)
- `ipdom` 只能是 U 型的无谓词形式: 它的 3 位谓词已经被并入立即数(§4.2)⇒ v0.1 那条"ipdom 的谓词必须为 p0"的约束,在 v0.2 里由编码本身保证,不再需要额外检查
- **recov 有效位的意义**: 如果没有它,一条忘了配 `ipdom` 的 `br.simt` 会悄悄沿用上一条 `ipdom` 的收敛点,得到"能跑但收敛点错"的内核 —— 这是最难查的一类 bug。加一位 valid、用后即清,使这类错误变成"发散时 recov 无效 → ERR_NO_RECOV 立即暴露"(§2.6)

### 5.8 分支(opcode 1100011)

```
br.simt label[, reconv]        ; 谓词字段 = 分支条件([28]=inv, [27:26]=psel)
```

- effective_mask 中谓词为真的 lane 跳转,其余 lane 顺序执行
- 均匀(全部满足/全部不满足)→ 普通跳转,不动栈;发散 → 压 SIMT 栈,精确规则见 §2.3.3
- **reconv 的默认值(PC+4)只对可证明均匀的分支合法**: 一旦发散,`recov_pc = PC+4` 意味着"收敛点就是未跳转路径的入口",taken 路径永远无法抵达。因此汇编器对**无法静态证明均匀**的 `br.simt` 必须要求显式 reconv,否则报汇编错误(附录 A)。这是 v0.1 最危险的一条默认值: 示例里始终显式写了 `, end`,但文字却把 PC+4 说成通用默认
- 目标地址 = `PC + sext(imm22)<<2`,范围 ±8MB(§4.2);**PC 相对 ⇒ 同一份内核代码可预加载到任意 SM 的指令 SRAM,无需重定位**
- `j label`(伪指令,@p0)恒为均匀分支,永远不需要收敛点,也不会压栈

### 5.9 伪指令

伪指令**不占编码空间**(只是汇编器记法),所以可以放心给足,免得为了可读性去新增真指令:

| 伪指令 | 展开 | 备注 |
|---|---|---|
| `mov rd, rs` | `add rd, rs, r0` | |
| `not rd, rs` | `xori rd, rs, -1` | 9 位立即数放得下 −1,所以"按位取反"不需要真指令 |
| `neg rd, rs` | `sub rd, r0, rs` | |
| `nop` | `addi r0, r0, 0` | |
| `j label` | `br.simt label`(@p0,不带收敛点、不生成 `ipdom`) | 恒为均匀分支 |

### 5.10 谓词语法

```
@p1  add  r3, r1, r2    ; lane 执行当且仅当 p1[lane]=1
@!p1 st.g 0(r10), r12   ; p1[lane]=0 才执行
add  r3, r1, r2         ; 无前缀 = @p0 = 不谓词化
```

- `@!p0` = 永假 = "关闭该 lane 的此指令",合法且有用(例如占位、调试时整体关掉某条指令)
- 取反位 `[28]` 是**逐 lane** 的: `@!p1 add ...` 在 p1=0 的 lane 上执行、p1=1 的 lane 上不执行
- **没有谓词逻辑运算**(andp/orp/notp,§10): 复合条件用"谓词化 setp 的条件写入"来拼(§5.4)

## 7. 内核示例 —— 用真实内核验证 ISA

**四个内核就是这套 ISA 的验收标准**(§1 的"最小够用"是反推出来的): 完整可汇编版本随 assembler.py 交付(Phase 2-3)。

- **执行前提**: 所有通用寄存器在 warp 启动时清零、p0..p3 为 (真,假,假,假)(§3.1)—— 这条写死之后,"屏蔽 lane 拿陈旧值算垃圾"这类行为才是可复现的,否则 RTL 与参考模型在未初始化寄存器上永远对不齐
- **覆盖面**(v0.2 起如实列出未覆盖项,而不是笼统说"覆盖全部")。分类与 §1 的九类一一对应,便于逐条核对:

### 7.1 clear: 帧缓冲填充(谓词 + 合并访存 + 均匀循环)

```
; clear.s — 用单一颜色填充整个帧缓冲
; 常量: [0]=N(像素数) [4]=color(RGBA8888) [8]=stride_elems
; 驱动契约: stride_elems == num_warps*8(必须严格相等!各 warp 的 idx = tid + wid*8
;   恰好覆盖 0..num_warps*8-1 且无重叠无空洞,前提就是这个步长;写成 ≥8 会漏元素)
; divu 除零会给出全 1,所以 stride_elems 不能为 0;N = 0 由下面的 T==0 判定挡住
; 帧缓冲基址 0x1000_0000
        lui   r10, 0x10000        ; fb_base(4KB 对齐 ⇒ 一条 lui 就够,§4.2)
        lui   r9,  0x2000         ; const_base = 0x0200_0000
        ld.g  r11, 0(r9)          ; N        ← 8 lane 同地址 → 合并器广播
        ld.g  r12, 4(r9)          ; color
        ld.g  r13, 8(r9)          ; stride_elems
        tmov  r16, tid            ; lane id
        wmov  r15, wid            ; warp id
        slli  r15, r15, 3
        add   r16, r16, r15       ; idx = tid + wid*8(各 warp 恰好覆盖 0..num_warps*8-1,无重叠无空洞)
        slli  r14, r16, 2
        add   r14, r14, r10       ; 每 lane 地址 = fb + idx*4
        slli  r15, r13, 2         ; 字节步长 = stride_elems*4(不用 imad:乘数是常量 4,装进寄存器反而多一条)
        addi  r17, r11, -1
        add   r17, r17, r13
        divu  r17, r17, r13       ; T = ceil(N/stride_elems) —— 标量循环次数(为什么必须标量见下)
        setp.eq p3, r17, r0       ; 退化情形 T==0 必须显式挡住,否则下面的 do-while 会死循环
        ipdom done
        @p3   br.simt done, done  ; 全 lane 同一条件 ⇒ 均匀跳转,不压栈
        mov   r18, r0             ; i = 0
loop:
        setp.ltu p1, r16, r11     ; p1 = idx < N。idx 单调增 ⇒ p1 只会由真变假,每轮重算即可(不需要 andp)
        @p1   st.g 0(r14), r12    ; 尾部谓词屏蔽;8 lane 地址连续 → 1 次 32B burst
        add   r14, r14, r15
        add   r16, r16, r13
        addi  r18, r18, 1
        setp.ne p2, r18, r17
        ipdom done
        @p2   br.simt loop, done  ; 条件分支必须显式给收敛点(汇编器在此前生成 ipdom)
done:
        exit
```

**为什么 `divu` 是必需而不是冗余**: 循环次数 T 必须是**标量**且全体 lane 相同,否则就成了逐 lane 循环;而本 ISA **没有 ballot/vote**(D11),硬件无法告诉内核"所有 lane 都做完了",光靠谓词写不出"全体完成才退出"。于是循环边界只能由标量算出 `T = ceil(N/stride_elems)`,这里 `divu` 是唯一手段(RV32M 的除法器现成)。这也解释了 §10 为什么把 ballot/vote 排在扩展路线第一位 —— 有了 vote,这类内核可以写成"逐 lane 判断 + 全体收敛",不必预先算 T。

**复核抓出的两个边界(已在上面修掉)**:

- **N = 0 时 T = 0 ⇒ 死循环**: do-while 会先执行一次循环体再比较 `i != T`,而那时 i = 1、T = 0,之后 i 只会继续增加、永不等于 0(v0.1 的写法)。v0.2 用 `setp.eq p3, r17, r0` + 均匀跳转把退化情形挡在循环之外(代价: 2 条指令,在循环外)
- **`stride_elems`(本内核,元素单位)与 §7.2 的 `stride_bytes`(字节单位)必须不同名**: v0.1 两处都叫 `stride` 却单位不同,错一个 ×4 就是整屏错位

**这个内核验证了什么**: `tmov`/`wmov`、常量广播读、谓词化 warp 级存储、跨 lane 合并 burst、均匀条件分支(含显式收敛点)、`divu`、常量物化(`lui`)。

### 7.2 gouraud: 顶点变换(FP32 + 谓词化访存 + imad)

```
; gouraud.s — 2D 仿射变换顶点 + 颜色透传(多 warp 通用)
; 常量: [0]=in_base [4]=out_base [8]=N [12]=m00 [16]=m01
;       [20]=m10 [24]=m11 [28]=tx [32]=ty [36]=stride_bytes(=24)
; 顶点: {x,y,r,g,b,a} 6×f32 = 24B;输出同布局,写入顶点输出缓冲
; 驱动契约: N ≤ num_warps*8(本内核不做 grid-stride 循环)
        lui   r9, 0x2000
        ld.g  r10, 0(r9)          ; in_base
        ld.g  r11, 4(r9)          ; out_base
        ld.g  r12, 8(r9)          ; N
        ld.g  r20, 12(r9)         ; m00
        ld.g  r21, 16(r9)         ; m01
        ld.g  r22, 20(r9)         ; m10
        ld.g  r23, 24(r9)         ; m11
        ld.g  r24, 28(r9)         ; tx
        ld.g  r25, 32(r9)         ; ty
        ld.g  r13, 36(r9)         ; stride_bytes
        tmov  r14, tid
        wmov  r15, wid
        slli  r15, r15, 3
        add   r14, r14, r15       ; idx = tid + wid*8(多 warp 分工,v0.1 只用 tid ⇒ 多 warp 会重复写同一顶点)
        setp.ltu p1, r14, r12     ; idx < N(尾部屏蔽)
        imad  r16, r14, r13, r10  ; in 指针  = in_base  + idx*stride_bytes ← 乘数已在寄存器 ⇒ imad 省一条 mul 和一个临时寄存器
        imad  r17, r14, r13, r11  ; out 指针 = out_base + idx*stride_bytes
        @p1   ld.g  r30, 0(r16)   ; x(被屏蔽 lane 不产生请求 ⇒ 无越界访问)
        @p1   ld.g  r31, 4(r16)   ; y
        fmul  r28, r30, r22       ; m10*x
        fma.f32 r28, r31, r23, r28 ; m11*y + m10*x   ← 屏蔽 lane 在算垃圾(见下面前提)
        fadd  r28, r28, r25       ; + ty → y'
        fmul  r27, r31, r21       ; m01*y
        fma.f32 r30, r30, r20, r27 ; x*m00 + m01*y → x'
        fadd  r30, r30, r24       ; + tx
        mov   r31, r28
        @p1   st.g  0(r17), r30
        @p1   st.g  4(r17), r31
        @p1   ld.g  r30, 8(r16)   ; r
        @p1   st.g  8(r17), r30
        @p1   ld.g  r30, 12(r16)  ; g
        @p1   st.g  12(r17), r30
        @p1   ld.g  r30, 16(r16)  ; b
        @p1   st.g  16(r17), r30
        @p1   ld.g  r30, 20(r16)  ; a
        @p1   st.g  20(r17), r30
        exit
```

**必须说清的两个前提(复核发现 v0.1 都没写)**:

1. **屏蔽 lane 会拿"没被加载的寄存器"参与 FP 运算**: `@p1 ld.g` 让屏蔽 lane 不产生请求 ⇒ 它们的 r30/r31 是陈旧值(由 §3.1 的"启动清零"保证可复现),后面几条 `fmul`/`fma`/`fadd` 照样在算 —— 注意 **`fma` 没有谓词字段**,无法逐 lane 关闭。这**只有在 (a) FP 非 trapping 且无副作用、(b) 结果最终被 `@p1` 屏蔽的 `st.g` 挡住,这两条同时成立时才无害**。内核作者必须自己确认结果不会绕过谓词写回(例如不要把它写进共享内存给别的 lane 用)
2. **索引里必须带 `wid`**: v0.1 只用 `tid`,于是 num_warps > 1 时所有 warp 处理同一批顶点(重复写同一片输出),而 N > 8 的顶点被静默丢掉

**一个真实的性能事实**: 顶点是 AoS 布局(24B/顶点),8 个 lane 的 x 字段地址相隔 24B ⇒ **x 的 8 次访问退化成 8 个分散请求**(§3.2 的第四种情形),而不是 1 次 burst;后面 r/g/b/a 的透传同样是逐字段 1 个请求。要恢复合并就得让顶点改成 SoA(x 数组、y 数组、颜色数组分开)—— 这是顶点格式的取舍,归 GFX.md 拍板。**注意 ISA.md 与 PLAN 的顶点格式目前并不一致**(PLAN §4 写的是 `{x, y(s16.15), r, g, b, a, u, v}`),本节示例用 6×f32=24B 只是示意:若最终采用 PLAN 的格式,则本内核的所有偏移、stride 以及"FP32 ↔ s16.15"的转换都要重写,而且 s16.15 的转换需要定点运算或新增转换指令 —— 这个接口必须在 GFX.md 里定死。

**这个内核验证了什么**: FP32 三条算术路径与 `fma` 单次舍入、谓词化载入/存储(尾部不越界)、`imad` 地址计算、常量内存读取、每 lane 独立的地址计算。

### 7.3 matmul: 32×32×32 FP32(共享内存 + barrier + FMA + 合并访存)

**前置条件(必须先说清,否则结果一定是错的)**:

- **规模固定 M = N = K = 32**(且都是 8 的倍数): 代码里的 `128`(M·4 / N·4)、`32`(tile 的 jj 步长)、`1024`(8·N·4)全是这个约束下的字面量。通用规模要把它们换成用 `imad` 以寄存器步长计算,并注意 9 位立即数上限: `addi ..., M*4` 只在 M ≤ 63 时可编码(§4.2)
- **num_warps = 4**: `row = wid*8 + tid` 覆盖 C 的 0..31 行;warp 少于 4 个则后面的行不会被计算,多于 4 个会越界。用 `bar.sync` ⇒ 必须单 SM 常驻(§2.2/§2.4),4 个 warp 正好是一个 SM 的容量
- **A 列主序(等价于 Aᵀ 行主序)、B 行主序**
- **共享内存按 warp 私有分区**: 每 warp 一块 8×8 tile = 256B,warp w 用 `[w*256, w*256+256)`。共享内存是 SM 级资源,不分区的话 4 个 warp 会互相覆盖对方的 tile(v0.1 就没有分区)

**循环结构有一条硬约束**: 只有 8 个寄存器能当 C 的累加器(r19..r26),它们对应**同一个 j 块里的 8 列** ⇒ **jb 必须是最外层**,顺序是「清累加器 → kb 内层累加 → 写回 8 个字 → 列指针 += 32」。代价: A 列块会被重复加载 4 次(jb 每轮一次)—— 若把 A 也放进共享、或想一次持有 32 个累加器,就要突破 32 个寄存器的预算,所以这个"重复加载"是寄存器预算的必然结果,不是疏忽。

```
; matmul.s — lane 计算 C 的第 row 行,row = wid*8 + tid
; 常量: [0]=a_base [4]=b_base [8]=c_base [12]=M(未用) [16]=N [20]=K(未用)
; 寄存器: r1=A 列基址 r2=b_base r3=C 行基址 r5=N r6=warp 共享区基址 r7=row*4
;         r8=A 指针 r9=kb 计数 r10=jb 计数 r11..r18=A 块(8 个 k) r19..r26=C 累加(8 个 j)
;         r27=tid*4 r28..r31=临时            (共 30 个通用寄存器,r4 空闲)
        lui   r9, 0x2000
        ld.g  r1, 0(r9)           ; a_base        (注意: r9 先当常量区基址,启动完成后被复用为 kb 计数器)
        ld.g  r2, 4(r9)           ; b_base
        ld.g  r3, 8(r9)           ; c_base
        ld.g  r5, 16(r9)          ; N(本内核要求 = 32)
        tmov  r7, tid
        wmov  r30, wid
        slli  r30, r30, 3
        add   r7, r7, r30         ; row = tid + wid*8
        slli  r7, r7, 2           ; row*4
        add   r1, r1, r7          ; A 第 row 列基址(A 列主序 ⇒ A[k][row] 随 k 以 M*4 步进)
        imad  r3, r7, r5, r3      ; C 行基址 = c_base + row*N*4 ← imad:乘数 N 已在寄存器
        wmov  r6, wid
        slli  r6, r6, 8           ; 共享区基址 = wid*256
        tmov  r27, tid
        slli  r27, r27, 2         ; tid*4:本 lane 负责 B tile 的第 tid 列
        addi  r10, r0, 4          ; jb = 4(倒数,最外层)

jb_loop:                          ; jb: 4→0
        mov   r19, r0             ; C[0..7] 清零(r19..r26,8 条 mov 展开)
        ... (r20..r26) ...
        addi  r9, r0, 4           ; kb = 4(倒数,内层)

kb_loop:                          ; kb: 4→0
        ; ── ① B tile(8k × 8j)搬进本 warp 私有共享区 ──
        ; 全局地址 = b_base + (kb-1)*1024 + (jb-1)*32 + tid*4
        ; 固定 k 时 8 lane 地址连续(32B)⇒ 1 次 burst ✓
        addi  r30, r9, -1
        slli  r30, r30, 10        ; (kb-1)*1024 = k 块偏移(8*N*4,N=32)
        addi  r31, r10, -1
        slli  r31, r31, 5         ; (jb-1)*32 = j 块偏移(8*4)
        add   r28, r2, r30
        add   r28, r28, r31
        add   r28, r28, r27       ; + tid*4
        add   r29, r6, r27        ; 共享槽 = warp 私有区 + tid*4
        ld.g  r30, 0(r28)
        st.s  0(r29), r30         ; addr[4:2] = (tid + kk*8) mod 8 = tid ⇒ 8 lane 落 8 个不同 bank ✓ 零冲突
        addi  r28, r28, 128       ; 下一 k 行(N*4 = 128,N=32)
        addi  r29, r29, 32        ; 共享内下一个 kk 行(tile 是 kk 主序 32B / jj 次序 4B)
        ... (kk=1..7 同模式,共 8 组) ...
        bar.sync                  ; ①→③ 栅栏:B tile 对本 SM 全部 warp 的 lane 可见

        ; ── ② A 列块(8 个 k)搬进寄存器 ──
        addi  r30, r9, -1
        slli  r30, r30, 10
        add   r8, r1, r30         ; A 指针 = 本 lane 的 A 第 row 列 + k 块偏移(必须带 r1!v0.1 漏了)
        ld.g  r11, 0(r8)          ; kk=0(列主序 ⇒ lane 间地址连续 ✓ 1 次 burst)
        addi  r8, r8, 128         ; M*4 = 128(仅当 M=32;M > 63 时 4M 超出 imm9,须改寄存器加法)
        ld.g  r12, 0(r8)          ; kk=1
        ... (kk=2..7 → r13..r18) ...

        ; ── ③ 计算:C[jj] += Σ_kk A[kk] × B_sh[kk][jj] ──
        ; jj 必须展开:8 个累加器分别对应 8 个 jj
        ; kk 必须展开:A[kk] 是按寄存器号选择的,ISA 不支持对寄存器堆变址
        ; 每个 (kk,jj) = 1 条 ld.s + 1 条 fma ⇒ 2 条指令/MAC
        ; B_sh[kk][jj] 地址 = r6 + jj*4 + kk*32:不含 lane 相关项 ⇒ 全 lane 同地址 = 广播(1 周期)
        ld.s  r28, 0(r6)             ; B_sh[0][0]
        fma.f32 r19, r11, r28, r19   ; C[0] += A[0] × B_sh[0][0]
        ld.s  r28, 32(r6)            ; B_sh[1][0]
        fma.f32 r19, r12, r28, r19   ; C[0] += A[1] × B_sh[1][0]
        ... (kk=2..7,累加器保持 r19) ...
        ld.s  r28, 4(r6)             ; B_sh[0][1]
        fma.f32 r20, r11, r28, r20   ; C[1] += A[0] × B_sh[0][1]
        ... (jj=1..7 同模式,累加器换 r20..r26;最大偏移 = 28+224 = 252 ≤ 255 ✓ 正好落在 imm9 内) ...

        bar.sync                  ; ③→① 栅栏:防止下一轮 tile 覆盖尚在读取的共享区
        addi  r9, r9, -1
        setp.ne p2, r9, r0
        ipdom kb_done
        @p2   br.simt kb_loop, kb_done
kb_done:
        ; ── ④ 写回本 jb 块的 8 列 C[row][j] ──
        st.g  0(r3), r19
        st.g  4(r3), r20
        ... (8 条,偏移 0..28) ...
        addi  r3, r3, 32          ; 下一个 j 块
        addi  r10, r10, -1
        setp.ne p2, r10, r0
        ipdom jb_done
        @p2   br.simt jb_loop, jb_done
jb_done:
        exit
```

**逐条核对 v0.1 的说法**(✅ = 成立,❌ = 不成立):

| 说法 | 结论 |
|---|---|
| A 列主序使 A、B 的**载入**全部合并 | ✅ 固定 k 时 8 lane 地址连续 32B ⇒ 1 次 burst |
| 共享"lane 各写一列 + 全 lane 广播读"零 bank 冲突 | ✅ 写侧成立;**读侧只在"地址不含 lane 相关项"时成立** —— v0.1 的 `add r30, r7, r0`(r7 = L*4)让基址随 lane 变化,实际读的是 `B_sh[kk][jj+L]`,既不是广播、结果也是错的,而且 jj+L > 7 时会溢出到下一个 kk 行。更糟的是 bank = (L+jj) mod 8 恰好不冲突,所以**不会靠 bank 冲突暴露出来** |
| `fma` 单次舍入、`bar.sync` 配对、倒数循环 trip 数(4/4/8) | ✅ 都对 |
| barrier 的使用前提 | ❌ v0.1 没声明 num_warps,也没做 warp 私有分区 ⇒ 多 warp 下互相覆盖 tile |
| "31/32 寄存器占用" | ❌ 实际用 30 个(r4 空闲)。v0.1 的"31"来自把 A 指针与 M*4 步长硬塞进同一个 r8 —— 那不是省寄存器,而是 bug 的来源 |
| C **写回**合并 | ❌ 不成立:lane 各占一行,同一条 `st.g` 的 8 个 lane 地址相隔 N*4 = 128B ⇒ 8 个单字请求。要合并就得改成"lane ↔ 列"的线程映射(那样 A 又只能从共享广播读) |

**v0.1 的内在错误清单(全部会算错,且冒烟测试抓不到)**: ① A 指针从未建立(r1 成死代码、r8 被写成步长 128,`ld.g r11, 0(r8)` 实际去读全局地址 128 的垃圾);② C 行基址二次缩放(`N*4 × L*4 = 16·L·N`,注释却写 `L*N*4`,除 lane 0 外全错);③ 循环嵌套反了(累加器跨 j 块混用,写回被放在所有循环之外只执行一次 ⇒ 只写出 C 的前 8 列);④ 共享读基址含 lane 项;⑤ 内层 8 条 fma 的下标错位(同一 jj 迭代里 8 个累加器拿到同一项);⑥ 无 warp 私有分区;⑦ 只用 `tid` 不用 `wid`。这些 bug 的共同点是"**能跑、不报错、lane 0 恰好正确、bank 不冲突**"—— 它们只能靠"指令级逐条复核 + 与 numpy 全元素比对"抓出来,这正是 PLAN.md §11 分层回归里"模块级 golden model"必须存在、且不能只比对第 0 行的原因。

**代码尺寸与执行代价要分清**(这里纠正 v0.2 早期版本的一处错误): ③ 段的 8×8 = 64 组 (ld.s + fma) 是**展开的静态代码**,加上搬 tile 的 8 组、A 块与写回,整个内核**静态约 220 条指令(≈0.9KB),只占 16KB 指令 SRAM 的 6%**。早先写的"约 3000 条、占四分之三"其实是**动态执行条数**(每 warp 每个 (jb,kb) 组合约 190 条 × 16 组合 ≈ 3000 条动态指令,对应 1024 次 MAC),不是代码尺寸 —— 所以"tile 不能再放大否则超 SRAM"的推论**不成立**。

真正的约束是**动态代价与编码/容量**: tile 缩小(如 4×8)代码更小,但 barrier 次数与全局 tile 流量翻倍;tile 放大(16×8)会让 `B_sh` 的偏移超过 9 位立即数(§4.2),共享占用也翻倍。**限制来自动态行为,不是指令 SRAM** —— 这类"静态/动态不分"的错误正是文档里最值得复核的地方。

### 7.4 abs: 逐 lane 条件(真实发散 —— 验证 SIMT 栈)

§7.1-§7.3 的分支**全部均匀**,一个都没碰 SIMT 栈;而栈是整套 ISA 里最难、最容易错的部件(PLAN 的 Phase 3c 专门留了一周做它)。验收必须有一个真发散的 kernel:

```
; abs.s — y[i] = |x[i]|,用 if/else 逼出真实发散(relu 是同形写法:把 neg 块换成 `mov r14, r0`)
; 常量: [0]=base [4]=N(元素为 FP32);驱动契约: N ≤ num_warps*8
        lui   r9, 0x2000
        ld.g  r10, 0(r9)          ; base
        ld.g  r11, 4(r9)          ; N
        tmov  r12, tid
        wmov  r13, wid
        slli  r13, r13, 3
        add   r12, r12, r13       ; idx = tid + wid*8
        setp.ltu p1, r12, r11     ; 尾部屏蔽
        slli  r13, r12, 2
        add   r13, r13, r10       ; 元素地址 = base + idx*4
        @p1   ld.g  r14, 0(r13)   ; x
        setp.flt p2, r14, r0      ; p2 = (x < 0) —— 与 +0.0f 比较(r0 的位型就是 +0.0f)
        ipdom join                ; 由汇编器自动生成,这里写出来是为了看见代价
        @p2   br.simt neg, join   ; ← 真正的发散点:x < 0 的 lane 走 neg,其余走 fall-through
        j join                    ; then 路径(x ≥ 0)什么都不做,直接去收敛点
neg:
        fsub  r14, r0, r14        ; x < 0 ⇒ -x
join:                             ; 两条路径在此会合;此处的指令只以"完整 mask"执行一次
        @p1   st.g 0(r13), r14
        exit
```

**这个内核要验证的 6 件事**(与 §2.3.3 的规则一一对应):

| # | 断言 | 为什么容易做错 |
|---|---|---|
| 1 | `br.simt` 部分 lane 跳转时压栈,帧内容 = `{recov_pc, fall_pc, mask_full, mask_pending, pending}` | 帧少一个字段时单层看不出来,嵌套必错 |
| 2 | taken 路径(`neg`)**先**执行 | 顺序反了结果仍"看起来对",但与 golden model 对不齐 |
| 3 | `neg` 路径落到 `join` 时 `pending = 0` ⇒ `pending ← 1`、切回未跳转 lane(x ≥ 0)并跳到 `fall_pc`(即 `j join`),**此时不执行 `join`** | 这里多执行一次会让 store 提前发生 |
| 4 | 未跳转 lane 执行 `j join` 落到 `join` 时 `pending = 1` ⇒ 弹栈,`active_mask` 恢复全 1 | 忘了弹栈会让后续指令一直以半个 mask 执行 |
| 5 | `join` 处的 `st.g` 以完整 mask 执行**一次** | |
| 6 | 全 lane 同号时**不压栈**(均匀分支,走 §2.3.1 的第二种) | 用全正、全负两个向量各跑一遍即可覆盖 |

- **嵌套发散**(if 里套 if)按同一模式再套一层即测栈深 2;栈深 8 的边界用 8 层嵌套的合成内核做压力测试(§2.6 的 SIMT_OVF 路径)
- `setp.flt p2, r14, r0` 是"与 +0.0f 比较": 若 x 是 −0.0f,`flt` 结果为假(−0.0 == +0.0),即"−0 不算负" —— 与 IEEE 语义一致,而这类边界值必须出现在测试向量里,否则实现者很容易写出"看符号位"的错误版本
- **逐 lane 迭代次数不同的循环也能正确执行**(只要收敛点设在循环出口): 但这会让每次迭代都付压栈/切换代价,这正是 §7.1 坚持用标量循环次数的原因,也是 §10 要加 ballot/vote 的原因

## 8. 微架构注释(与 RV32IMF 的映射)

| 模块 | 实现建议 |
|---|---|
| lane 数据通路 | **直接复用 RV32IMF 的 ALU/FPU/乘法器逻辑**,每 lane 一份(8 份;面积小)。FP 单元按 RV32F 语义例化;`imad` 复用已有的乘法器 + 加法器,不新增功能单元 |
| 寄存器堆 | 每 warp: 8 lane × 32 × 32b = 1KB,每 lane 独立 2R1W bank —— 无跨 lane 端口,设计简单 |
| **寄存器初值** | warp 启动时清零全部通用寄存器与 p1..p3(§3.1)。实现可以是 launch 时花几个周期刷寄存器堆,或每 lane 加一位 valid、读未写过的寄存器返回 0。目的只有一个: 让"屏蔽 lane 拿着没加载的寄存器参与运算"产生的垃圾值是**确定值**,否则 RTL 与参考模型永远无法逐位对齐 |
| fma 三操作数 | 2 周期读操作数(rs1/rs2 第 1 周期,rs3 第 2 周期)或 3 读口;in-order 核只需停一拍,多 warp 交错掩盖 |
| 合并器 | warp LSU 内比较 8 个 lane 地址 → 生成 burst 请求队列;同地址→广播;屏蔽 lane 剔除 —— §3.2 的四种情形直接对应四段逻辑 |
| SIMT 栈 | 每 warp 8 深 × `{recov_pc, fall_pc, mask_full, mask_pending, pending}`(≈3×32b/帧,§2.3.2);"路径完成"就是一个"PC == 栈顶 recov_pc"比较器 + `pending` 状态机 |
| recov 寄存器 | 每 warp 一个 32b recov + 1 位 valid;`ipdom` 写入并置 valid,`br.simt` 用后清 valid;发散时 valid=0 ⇒ ERR_NO_RECOV(§2.6) |
| barrier | 每 SM 一套 `{arrived_count, generation}`(单实例 barrier 的红利:不需要 per-warp 到达位图,§2.4) |
| 错误状态 | 每 SM 一个错误码寄存器 + 停机逻辑(§2.6 的表);MMIO 可读、host 可复位 |
| 调度 | 4 warp 轮流分派(**FGMT**,fine-grained multi-threading:每周期从"就绪"的 warp 里挑一个发射,访存/barrier 挂起的 warp 让出);其余 warp 掩盖延迟 —— GPU 的核心思想 |
| 写缓冲 | 每 SM 一个小的全局写合并缓冲(write-combine buffer,约 4~8 项):`st.g` 先入缓冲、按地址合并;**`exit` 与 `bar.sync` 负责冲刷**(§2.4/§2.5 的可见性保证都依赖它) |
| 指令存储 | CP 预加载内核到 SM 指令 SRAM(**16KB = 4096 条**),无 icache |
| 共享存储 | 每 SM 16KB 多口 SRAM,8 bank × 32b,bank = addr[4:2](§3.2);与指令 SRAM 是**两块独立存储** |

### 8.1 性能模型(设计目标值 —— 不是实测值)

写内核的人需要知道"什么贵",所以给出目标值。这些数字是设计意图,**首次综合/仿真后必须回来标定**,并把实测值补在本表里(否则它会变成一份没人信的文档)。

| 项 | 目标 | 说明 |
|---|---|---|
| 分派 | 1 条指令/周期/SM | 4 warp 轮转(FGMT);每 warp 一条指令覆盖 8 lane ⇒ 目标 8 lane-指令/周期 |
| 均匀分支 | 不压栈、不切 mask | 但每条条件分支前仍有 1 条 `ipdom`(汇编器生成)—— 所以 §2.3.1 说的"零开销"指的是**不付栈的代价**,不是零指令 |
| 发散分支 | 压栈 1~2 周期,两条路径**串行**执行 | 发散块的墙钟时间 ≈ 两条路径时间之和,所以内核应尽量均匀 |
| FP32 算术 | 全流水 | 具体延迟取决于复用 RV32F 的实现;靠多 warp 掩盖 |
| `div`/`divu`/`rem` | 多周期(迭代式除法) | 尽量放在循环外 —— §7.1 的 divu 每 warp 只执行一次 |
| `ld.g`/`st.g` | 合并成 burst 时 1 次请求;分散时最多 8 次 | 延迟靠多 warp 掩盖(§3.2 四种情形) |
| `ld.s`/`st.s` | 无冲突 1 周期;广播 1 周期;同 bank 异地址则串行化 | §7.3 的 tile 布局就是为"1 周期广播"设计的 |
| 指令 SRAM | 4096 条上限(静态代码) | §7.3 的 matmul 静态约 220 条、动态每 warp ≈3000 条 —— 限制 tile 尺寸的是**动态 barrier 次数与共享容量**,不是代码大小(§7.3 末尾的说明) |

> **内核优化的优先级(收益/成本排序)**: ① 提高访存合并度 → ② 用均匀分支替掉发散分支 → ③ 消除共享 bank 冲突 → ④ 用 `imad`/`fma` 合并指令 → ⑤ 把 `div`/`rem` 移出循环。这也解释了为什么 §7.3 的 A 列主序和 tile 布局值得在文档里写清楚: 它们属于第 ①③ 类收益,改一行布局就能换来成倍的访存效率。

## 9. 设计决策记录 (ADR)

| # | 决策 | 理由 / 代价 |
|---|---|---|
| D1 | warp = 8 lane | 教学规模;32 lane 调试代价陡增。8 lane 也正好让"4 warp × 8 lane = 32 线程/SM"与 PLAN 的 `<<<num_warps, 8>>>` 对齐。升级路径: 提高 vlen |
| D2 | pred 统一在 [28:26],I/S 型 imm 压缩为 9b | 编码统一 > imm 宽度: 谓词化是 SIMT 每条指令都要用的东西,位置恒定让译码只有一条路径。代价: (a) I/S 立即数只有 ±255 —— 四个内核的偏移都在范围内;(b) 非 4KB 对齐常量的构造变贵(§5.5)⇒ 常量一律走常量内存;(c) U 型因此必须放弃谓词字段(§4.2)。**已否决的备选**: 2b pred + imm10(丢掉 `@!p`,而 `@!p` 正是 §5.4"条件写入"写法的基础); 按格式分别放 pred(省一位却把译码分派复杂化) |
| D3 | 仅 32 位字访存 | 合并器简化一个数量级;字节打包用逻辑指令。代价: RGBA8888 的按通道写要读-改-写(所以 §7.1 直接写整字);字节/半字访存排在 §10 |
| D4 | fma 无谓词字段 | R4 型没有空位;active mask 自动屏蔽已保证正确性(前提: FP 非 trapping、无副作用)。代价: **比 active_mask 更细的条件累加不能用 fma**,必须退回带谓词的 `fmul`+`fadd` 或重排成分支 —— 这条限制写进了 §4.3 与 §7.2 |
| D5 | exit 必须均匀 | 非均匀退出的语义复杂,初版不做;尾部处理走谓词。代价: 内核无法让"已完成的 lane 提前退出"来省时间 |
| D6 | 全部 warp 常驻,无多波次 | 使 barrier = kernel 级同步,概念清晰。代价: 每 kernel ≤ 8 warp(用 barrier 时 ≤ 4) |
| D7 | 单实例 barrier + 同 SM 约束 | 命名 barrier / 跨 SM barrier 留待扩展。红利: 硬件只需一个到达计数器(§2.4) |
| D8 | 参数走常量内存 | 无 ABI 设计负担;合并器广播读,零额外硬件。代价: 每次读参数都要过访存路径 ⇒ 内核应一次性 ld.g 到寄存器复用(§7 都是这个模式) |
| D9 | setp 目标仅 p1..p3 | p0 硬连线恒真;`@!p` 覆盖取反需求 |
| D10 | br.simt 显式收敛点操作数 | 收敛点由编译器/汇编器给出,硬件不做分支预测、不做收敛推断。代价: 每条条件分支前多 1 条 `ipdom` |
| D11 | 无 atomics/ballot | 初版内核不需要;列于扩展路线。**连带后果值得记住**: 没有 vote ⇒ 循环次数必须由标量算出 ⇒ `divu` 从"可选"变成"必需"(§7.1) |
| D12 | 新增整数 `imad`(R4 型 funct3=001) | "基址 + 索引×步长"在目标内核里出现 3 次(gouraud 2 次、matmul 1 次),用 mul+add 要 2 条指令且多占临时寄存器;硬件复用已有乘加器 ⇒ 面积增量≈0。已否决备选: 让汇编器做 mul+add 合并(需要证明目标寄存器死亡,不如一条真指令干净、可读) |
| D13 | setp 改用 R 型的字段位置: `cond[31:29]` + `family=funct3` + `pdest=rd` | v0.1 的 setp 图有 bit 28/27(`family` 与 `pred`)和 bit 24..20(`op` 与 `rs2`)两处重复占用,**无法译码**。修完顺带把条件扩到 6 个(le/gt/feq/fne 全部到位),代价为 0 —— 用到的都是原本空着的位 |
| D14 | 非法情形一律做成**可检测的架构错误**,不写"未定义行为" | 栈溢出、未对齐、发散中 barrier、漏 `ipdom` 都能用 1~2 个比较器检出(§2.6)。理由: 单人项目的调试预算最贵,而"未定义行为"在仿真里表现为安静的错数据。代价: 每 SM 一个错误码寄存器 + 停机逻辑 |
| D15 | SIMT 栈帧含 `fall_pc` 与 `mask_pending` | 缺 `fall_pc` 则嵌套发散无法恢复 else 入口;缺 `mask_pending` 则因 taken 路径会改写谓词而无法反推未执行 lane(§2.3.2)。代价: 帧从 3 字段变 5 字段(≈3×32b),8 深栈也只有 ~96B/warp |
| D16 | `lui`/`ipdom` 放弃谓词字段,换 20 位立即数 | 保留 pred 则立即数只剩 17 位,`sext(imm17)<<12` 连 0x1000_0000 都够不到(§4.2);而"条件地装常量"没有任何用途 ⇒ 3 位 pred 是纯损失。代价: 这两条指令不可谓词化 |
| D17 | LAUNCH 带 `flags`,CP 连续打包并校验 barrier | 让"bar.sync 要求 num_warps ≤ 4 且同 SM"从口头约定变成可强制的分发前置条件(§2.2);否则多 SM 的 barrier 会静默死锁。代价: LAUNCH 多一个字段、CP 多一条校验(字段位置待 CMDS.md 定) |
| D18 | warp 启动时寄存器与谓词清零 | 让"屏蔽 lane 参与运算"的垃圾值确定化,参考模型才能逐位对齐(§3.1、§7.2)。代价: launch 时清寄存器堆(或每 lane 一位 valid) |
| D19 | `ipdom` 独占 opcode `1010111`(RV custom-0 槽),不再与 `bar.sync`/`exit`/`tmov`/`wmov` 共用 `0101011` | 共用时 funct3 既要选指令、又落在 `ipdom` 立即数的 `[14:12]` 里 —— **两者互斥**: 按 funct3 译码则 imm20 低 3 位必须为 0,收敛点只能落在 32B 对齐地址,文档里 6 处 `ipdom` 全部不可译码。`ipdom` 写的是 warp 级的 recov 寄存器,和写 `rd` 的 `tmov`/`wmov` 本就不是同类。代价: 多占 1 个 opcode(还有 118 个空位),换来 U 型格式统一为 imm20 |

> **尚待拍板的决策(依赖其它文档)**: 顶点格式与 FP32↔s16.15 转换(GFX.md,见 §7.2 的冲突提示); LAUNCH `flags` 与错误状态寄存器的位定义(CMDS.md); 微 tile 尺寸 8×8 vs 4×8(代码大小 ↔ barrier 次数,§7.3)。

## 10. 已知限制与扩展路线

**限制(故意为之,但每一条都写清后果):**

- 无字节/半字访存;无本地内存/栈(不可递归,因此也没有栈指针);无异常陷阱(非法情形改为可检测的架构错误,§2.6)
- 无 FP 除法/开方、无 FP64/FP16;浮点只有 FP32
- 每 kernel ≤ 8 warp(用 barrier 时 ≤ 4 且必须同 SM);SIMT 栈深 8;指令 SRAM 4096 条
- 无 atomics、无 ballot/vote、无 tex.sample、无 icache(内核必须 ≤ 4096 条)
- **发散块内的路径不能"跳出去"**(必须先汇到收敛点,§2.3.4)—— 解除它需要 convergence barrier 或每 lane PC
- `fabs`/`fneg` 需要掩码,而掩码的构造代价取决于对齐: `fneg` 的 0x8000_0000 恰好 4KB 对齐(`lui rX, 0x80000`)+ `xor` = 2 条指令;**`fabs` 的 0x7FFF_FFFF 不是 4KB 对齐**,按 §5.5 要 2~3 条指令 ⇒ 在循环里很贵。这也是把 fabs/fneg 放进扩展路线的原因(或者把两个掩码预置在常量内存里、用 `ld.g` 读一次复用)

**扩展路线(按优先级,每条给出"为什么排这个位置"):**

| 优先级 | 扩展 | 为什么排这里 | 代价 |
|---|---|---|---|
| 1 | ballot / vote(active mask → 寄存器、any/all) | 归约类内核的钥匙,也是"逐 lane 循环"的钥匙 —— §7.1/§7.4 的写法都是被它的缺失逼出来的;硬件上只是把 active mask 读出来 | 极小 |
| 2 | 谓词逻辑 andp / orp / notp | 目前只能靠"谓词化 setp 的条件写入"(§5.4)凑复合条件,表达力有限 | 小(谓词 ALU) |
| 3 | fabs / fneg / fsqrt / fdiv(用 R4 或 FP 的空 funct4 槽) | 像素着色迟早要用;当前连 fabs/fneg 都得绕常量内存 | fsqrt/fdiv 面积大,可只做一个或走查找表 |
| 4 | byte/half 访存 + 打包/解包 | 纹理与帧缓冲的按通道访问;D3 的简化正是从这里省下来的 | 合并器要处理混合宽度 |
| 5 | atomics(建议 opcode 0101111,与 RV32A 同位) | 输出累加归约、直方图 | 中等,需定义内存序 |
| 6 | convergence barrier / 每 lane PC | 解除"发散块内不能跳出去"的限制(可参考 NVIDIA Volta 的每线程 PC) | 大(栈机制重构) |
| 7 | 命名 barrier / 跨 SM barrier / 多波次调度 | 解除 warp 数上限与 SM 绑定 | 大(调度器 + 同步) |
| 8 | FP16、tex.sample、local memory | 纹理/矩阵负载与栈式分配 | 各自独立,可按需插入 |

```
谓词前缀: @p1 / @!p1(省略 = @p0)
标签: name:

    br.simt target[, reconv]      ; 谓词字段即分支条件

MMIO: CP 状态、错误码、`sm_done` 的地址与位定义见 CMDS.md(本文档只规定语义)
```

**本轮优化的取舍原则(后续修改本文档时建议沿用):**

1. **能跑但结果错的,必须有判据** —— 位宽之和 = 32、覆盖率表、循环 trip 数、与 golden model 的比对粒度;
2. **"未定义行为"一律消灭** —— 要么给出精确定义,要么换成可检测的架构错误;
3. **每条指令都要有数据流依据** —— `imad` 因"乘数已在寄存器里"而加入,也因 clear 里"乘数是常量"而不用(§5.3);
4. **性能结论必须标注前提** —— "广播读零冲突"的前提是"读地址不含 lane 相关项",而"写回合并"根本不成立(§7.3)。
